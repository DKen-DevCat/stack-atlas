# 27. 設計: ライブを製品にする（Phase 10-2）

作成: 2026-11-12。**状態: 下書き。設計レビュー（実装の前に 1 回。§10）の前。** 要件は docs/24、もとの設計は docs/25 §3.5（D206〜D209）、図の形は docs/26。決定の番号は **D228 から**、質問の番号は **Q39 から**。

## 1. 結論

試し（`prototype/live/`。ユーザーの了承済み）を、`stack-atlas live` という 1 つのコマンドにする。

- 人が、手元で起動した本物のアプリを操作する。道具は、**押した部品・ブラウザから出た通信・画面の変わった所**を見て、その部品から始まる挙動の経路を光らせる
- 見せ方は、試しと同じ: **記録してから再生する**（再生・一時停止、時間に比例した再生バー、見せる速さ 0.1〜1 倍。操作の部品に文字は出さない）
- 試しから変える所は 3 つ:
  1. **通信は、ブラウザの外（道具の側）から見る**（試しは、アプリの中の通信の口を包んでいた）。アプリの動きに触らず、通信の口の種類を選ばない
  2. **手元の外へは、書きこませない**（試しには無かった守り。D207）
  3. **通信の中身の値は、既定で出さない**（試しは、そのまま出していた）

## 2. 目的・やること・やらないこと・できたと言える条件

**目的**: 「ここを押すと、この流れで、こう画面に反映された」を、本物のアプリの上で追えるようにする（docs/24 の核。ユーザー、2026-11-11）。

**やること**

1. `stack-atlas live [<dir>] --url <手元の URL>`: 図（`<dir>/.stack-atlas/`）を検査し、道具がブラウザの窓を開く。左にアプリ、右に挙動の一覧と経路
2. 1 回の操作について、次の順に見せる: 押した部品 → 経路 → 実際に送ったもの → 実際に返ったもの → 画面の変わった所
3. 段ごとの、実際にかかった時間（時間の内訳）
4. 図に書かれた通信と、実際に出た通信の照合（合っている・図にあるが出なかった・図に無い）
5. 守り: 手元だけ・書きこみを止めて見る・値を伏せる・保存しない（§5）

**やらないこと**（この段階では）

- 道具が、アプリを押すこと（操作するのは人だけ。確かめのための自動の操作は、テストの中だけ）
- 写しを使う入口（10-3b）、根拠・未読・古さの検査（10-1b）
- 通信・画面の記録を、ファイルに残すこと。共有すること
- 通信をわざと遅くすること（遅い回線のまね）
- ログインの状態を、次の回に持ちこすこと（Q40）

**できたと言える条件**

| # | 条件 | 確かめ方 |
|---|---|---|
| 1 | サンプルのアプリ（`prototype/live/app`）で、開く・投稿する・削除するの 3 つの挙動が、操作に合わせて光り、送ったもの・返ったもの・画面の変わった所・時間の内訳が出る | ブラウザを動かす自動の確かめ（試しの `--check` の 13 項目を引き継ぐ） |
| 2 | 図は、エージェントが書いたもの（`fixtures/atlas-live-agent`）を、手を入れずに使う | 同上（入力を、その図にする） |
| 3 | 手元の外への書きこみが、1 つも外へ出ない。「止めて見る」のときは、手元への書きこみも出ない | 受け側のサーバーが受けた通信を数えるテスト（返事を差し替える仕組みを素通りする通信・画面を離れるときに送る通信も含む） |
| 4 | 値は、既定では出ない（キーの名前と型だけ）。押したときだけ出る。ファイルにも端末にも残らない | 道具がライブの画面へ渡した出来事を調べるテスト |
| 5 | 図・アプリから来た文字が、ライブの画面で HTML として解釈されない | 名前・文・通信の中身に、タグの形の文字を入れたテスト |
| 6 | 枠に入るのを拒むアプリでも、見られる（別の窓） | 拒む応答を返す小さなサーバーでのテスト |
| 7 | 道具の中に、特定の言語やフレームワークを前提にした処理が無い（docs/24） | 差分の読み直し。見るのは、ブラウザの出来事と、図だけ |

仕事の repo で使えること（docs/24 の条件 1・2）は、10-3 で確かめる。ここでは確かめない。

## 3. 全体像

```
stack-atlas live <dir> --url http://localhost:3000/
 │
 ├─ 図を読んで検査する（誤りがあれば、開かずに終わる）。まとめた図は、メモリの中だけに持つ
 ├─ 手元のサーバー（ループバックだけで聞く）: ライブの画面と、まとめた図を配る
 └─ ブラウザ（道具が開く窓。毎回、空の利用者の領域）
      ├─ ライブの画面（ビューア）          ← 道具が、見た出来事を渡す
      │    ├─ 左の枠: 本物のアプリ（--url）
      │    └─ 右: 挙動の一覧・経路・再生・時間の内訳・画面の変わった所
      └─ 見張り（道具の側）
           ├─ 通信: ブラウザの外から見る・止める
           └─ 押した部品と、画面の変化: 枠の中の小さなスクリプトが見て、道具にだけ知らせる
```

出来事の流れは、一方向にする: **アプリ → 見張り（道具） → ライブの画面**。ライブの画面は、アプリの枠と直接は話さない。

## 4. 構造

### 4.1 置き場

| 場所 | 中身 | 依ってよいもの |
|---|---|---|
| `packages/wiring/src/live/` | 出来事の形（道具とライブの画面の間の約束）、操作への区切り、時間の内訳、画面の変化の差、図との照合、値を伏せた形。どれも純粋な計算 | `@stack-atlas/schema` |
| `packages/live/`（新しいパッケージ） | 見張り: ブラウザを開く、通信を見る・止める、枠の中のスクリプト、手元のサーバー | schema・wiring・core、ブラウザを動かす部品（ビューアの e2e・画面を撮る抽出器と同じもの。同じ版） |
| `packages/viewer/`（`live.html`・`src/live/`） | ライブの画面。`behaviorView` で経路を並べ、渡された出来事を再生する | schema・wiring だけ（今までどおり。core にも live にも依らない） |
| `packages/cli/src/commands/live.ts` | 引数を読み、図を検査し、見張りを起動する。見張りは、要るときだけ読みこむ | core・live |

### 4.2 見るもの

| 見るもの | どこで見るか | 理由 |
|---|---|---|
| ブラウザから出た通信（メソッド・パス・状態・時間・中身） | ブラウザの外（道具の側） | アプリの中の通信の口を包まない。通信の口の種類（古い口・新しい口・フォームの送信・画面を離れるときに送る通信）を選ばない。返事を差し替える仕組みが受けた通信も見える（試しで確かめた） |
| 押した・入力した・送信した要素が、図のどの部品か | アプリの枠の中の小さなスクリプト | 要素とセレクタの照らし合わせは、画面の中でしかできない |
| 画面の変わった所（足された・消された要素） | 同上 | 同上 |
| アプリの画面のアドレス（どの画面を開いているか） | ブラウザの外 | 枠の移動は、道具の側から見える |

枠の中のスクリプトは、**見るだけ**: 何も押さない・通信を変えない・画面を変えない・アプリの持ち物（関数・変数）を置き換えない。見たことは、道具が用意した専用の口で、道具にだけ知らせる（窓どうしの知らせは使わない。試しは、宛先を選ばない知らせを使っていた）。

- 図のセレクタは、要素とセレクタを照らす関数に渡すだけ。評価する文に埋めこまない。形のおかしいセレクタは、その部品だけ飛ばす
- 道具は、専用の口から来た知らせを、**知らせた枠の出所**で確かめる（アプリの出所の枠からだけ受ける）。形と大きさも確かめる（文字は長さの上限、列は数の上限）

### 4.3 操作への区切りと、再生（`packages/wiring/src/live/`）

- **操作**は、部品の出来事（押す・送信・入力・変更）か、画面を開いたことで始まる。そのあとの通信と画面の変化を集め、**通信がすべて済み、しばらく何も起きなくなったら**、操作が済んだとみなす（試しと同じ）
- **どの挙動か**: 始まり（部品と、操作の種類。開いたときは画面）が合う挙動。合う挙動が 2 つ以上あるとき（分岐で分かれるもの）は、実際に出た通信と、経路の通信の段が、いちばん多く合うものを選び、ほかも候補として出す。合う挙動が無いときは、**図に無い操作**として、見えた通信だけを並べる
- **時間の軸**: 操作の始まり → 通信ごとの「送ってから返るまで」 → 最後の画面の変化。段の長さは、実際にかかった時間。再生は、この軸の上を進む
- **画面の変化の差**: 一覧を丸ごと描き直すアプリでは、全部が「消えて、増えた」に見える。同じ中身の「消えた」と「増えた」を打ち消して、差だけを出す（試しで分かったこと）
- **図との照合**: 経路の段のうち、画面の側から受け口へ出る通信の段（`behaviorView` の `request`）と、実際の通信（メソッドとパス）を比べる。パスの中の、値が入る所（`{id}` などの形）は、どの値とも合うとみなす。結果は 3 つに分ける: 合っている・図にあるが出なかった・図に無い

経路のうち、実際に見えるのは、ブラウザから出る通信まで。その先（受け口からデータの置き場まで）は、図に書かれた段を出す。**実際に見えた段と、図に書かれただけの段は、見た目を分ける**（試しと同じ。実線と破線）。

### 4.4 ライブの画面（`packages/viewer`）

- 並びは、了承済みの試しと同じ: 左にアプリ、右に、挙動の一覧・経路（上から下へ）・再生の操作・時間の内訳・画面の変わった所。**アプリの画面の上に、道具の面（パネル）を重ねない**
- 再生の操作は部品だけ（文字を出さない）: 再生・一時停止、段ごとに色を分けた再生バー（幅が実際の時間に比例。いちばん長い段は色を変える）、見せる速さのつまみ（0.1〜1 倍）
- 足す部品（どれも、絵だけで表す。意味は、マウスを乗せたときの説明と、読み上げ用の名前で補う）:
  - **値を見る**（目の絵。既定は切）: 入れると、その操作の通信の値が出る（§5.3）
  - **止めて見る**（盾の絵。既定は、起動のときの指定）: 入れると、書きこむ通信を、出る直前で止める（§5.2）
- 押した部品と、変わった所を囲む枠は、アプリの枠の上に線だけで描く（試しと同じ。前の操作の枠は残さない）。アプリが別の窓のとき（§4.5）は、囲む枠は出さず、右の一覧に名前で出す
- 図・アプリから来た文字（名前・文・パス・通信の中身・画面の文字）は、**すべて文字として出す**（HTML として組みこまない）
- 画面の文言は日本語

### 4.5 アプリの置き方

- **既定は、ライブの画面の左の枠に入れる。** ライブの画面は、アプリと同じ名前（`localhost` など）の、別のポートで配る（D234）。名前が同じなので、アプリの Cookie は枠の中でも送られる。ポートが違うので、アプリの中のスクリプトから、ライブの画面の中は読めない
- **枠に入るのを拒むアプリ**（応答のヘッダで拒むもの）は、**別の窓**で開く（D235）。見張りは道具の側にあるので、見えるものは変わらない。応答のヘッダを書き換えて枠に入れることは、しない（道具は、通信を変えない）
- アプリが、手元ではない所へ移ったとき（外へのリンクなど）は、見るのをやめ、移ったと出す

### 4.6 図に足すもの: 画面のアドレス

「画面を開く」挙動と、いま開いている画面を結ぶために、**画面の箱に、任意の `meta.path`（その画面のアドレスのパス。例 `/articles/{id}`）**を書けるようにする（D237）。

- 無いとき: 画面の箱が 1 つなら、それとみなす。2 つ以上で決まらなければ、右の一覧で、利用者が画面を選ぶ
- 手順書（`harness/guide/`）に 1 行足す。契約 v0 のまま（任意の項目を足すだけ）。今ある図（画面が 1 つ）は、そのまま動く

## 5. 安全

守るもの: 共有の環境・本番（書きこませない）、通信の中の秘密（出さない・残さない）、利用者の手元（図やアプリの文字に、道具を操らせない）。

### 5.1 信用しないもの

| もの | 扱い |
|---|---|
| 図（エージェントが書く） | 検査を通ったものだけ使う。セレクタは照らすだけ。名前・文は文字として出す。図の `request` は、実際の通信と**比べるだけ**に使う（道具が、図をもとに通信を送ることはない） |
| アプリ（の中のスクリプト） | 専用の口に、にせの知らせを送れる前提で作る。知らせで変わるのは、ライブの画面の表示だけ。道具の側の動き（何を止めるか・値を出すか）は、アプリからの知らせでは変わらない |
| 通信・画面の中身 | 大きさに上限。文字として出す |

### 5.2 手元だけ（D207）

- **開く URL は、手元だけ。** 名前が、ループバックのアドレス（`127.0.0.0/8`・`::1`）だけに解けること。そうでなければ、開かずに終わる（終了コード 2）。名指しで外につなぐ引数は、作らない
- **書きこむ通信（読むだけの通信ではないもの）は、手元宛てだけ通す。** 手元ではない宛先への書きこみは、**いつも止める**（切る引数・設定は、作らない）。止めた通信は、「止めた」と出し、送ろうとした中身の形を見せる
- **「止めて見る」**: 手元宛ての書きこみも止める。アプリからは、通信の失敗に見える。どこにも書かれない
- 止める仕組みは、ブラウザの外（道具の側）に置く。返事を差し替える仕組みを素通りする書きこみ・画面を離れるときに送る通信にも効くことを、試しで確かめた（2026-11-12。受け側に届いたのは、読むだけの通信だけ）
- 返事を差し替える仕組みが、ブラウザの中で返事を作った通信は、もともと外へ出ない。「ブラウザの中で返事が作られた」と出す
- つなぎっぱなしの通信で、手元ではない宛先のものは、つながせない
- 読むだけの通信は、手元ではない宛先でも通す（Q39。字形・地図の絵などを外から読むアプリが、動かなくなるため）。宛先が手元ではないことは、表示に出す

### 5.3 秘密

- 通信の中身は、**道具の側で、値を伏せた形にしてから**、ライブの画面へ渡す。渡すのは、キーの名前と、値の型（文字・数・真偽・列の長さ）だけ。問い合わせの文字列も、キーの名前だけ。ヘッダは、名前も値も渡さない（内容の種類を除く）
- **「値を見る」**を利用者が入れたときだけ、その操作の通信の値（上限つき）を渡す。入れる合図は、ライブの画面の枠からのものだけを受ける（アプリの枠からは受けない）
- 値は、道具のメモリの中に、直近の操作の分だけ持つ。**ファイルに書かない。端末にも出さない。** 窓を閉じると消える
- ブラウザは、毎回、空の利用者の領域で開く（ふだんのブラウザの Cookie・保存したパスワードは、見えない）

### 5.4 手元のサーバー

- ループバックだけで聞く。Host ヘッダが、手元の名前でなければ断る（今の `serve` と同じ守り）
- 配るのは、ライブの画面（ビューアをビルドしたもの）と、まとめた図だけ。対象の repo の中のファイルは配らない
- ライブの画面には、読みこみ元を絞るヘッダを付ける（スクリプトは自分の出所だけ・枠はアプリの出所だけ）

### 5.5 残る危なさ

| # | 危なさ | 扱い |
|---|---|---|
| 1 | 読むだけの通信が、共有の環境に届く（読むだけで何かが変わる作りのもの） | 通す（Q39）。宛先が手元ではないことを、表示に出す |
| 2 | 手元のバックエンドが、その先の共有の環境に書く | 道具からは見えない。「手元で起動した環境」は、その先も手元であること、と使い方に書く |
| 3 | ブラウザの外から止められない通信の口が、ほかにある | 確かめた口（§5.2）を、テストで固定する。確かめていない口は、§9 に書く |
| 4 | 「値を見る」を入れたまま、画面を人に見せる | 入れているあいだ、目の絵の色を変える。次に起動したときは、切に戻る |

## 7. 決めたこと

| # | 決定 | 理由 |
|---|---|---|
| D228 | 通信は、ブラウザの外（道具の側）から見る。アプリの中の通信の口を包まない | アプリの持ち物を置き換えると、アプリの動きを変えうる。口の種類ごとに包む必要も無くなる。止める仕組みと、同じ場所に置ける |
| D229 | 押した部品と、画面の変化は、枠の中の小さなスクリプトが見て、道具が用意した専用の口で、道具にだけ知らせる | 要素とセレクタの照らし合わせは、画面の中でしかできない。窓どうしの知らせは、宛先と送り主の確かめが要り、アプリが別の窓のときに使えない |
| D230 | 出来事は、アプリ → 道具 → ライブの画面の一方向。ライブの画面は、道具が渡した出来事だけを使い、すべて文字として出す | アプリと、ライブの画面を、直接つながない。守りを、道具の側の 1 か所に集める |
| D231 | 開く URL も、書きこむ通信の宛先も、手元（ループバックに解ける名前）だけ。手元ではない宛先への書きこみは、いつも止める。切る手段は作らない | D207（環境を汚さない。名指しの抜け道を作らない）。手元のフロントが、共有のバックエンドにつながっている構成でも、汚さない |
| D232 | 「止めて見る」は、起動のときの引数（`--hold-writes`）と、ライブの画面の部品の両方で切り替えられる。切り替えの合図は、ライブの画面の枠からだけ受ける | 手元でも汚したくないときに、その場で入れられる |
| D233 | 通信の値は、道具の側で伏せてから渡す。「値を見る」を入れた操作の分だけ、値を渡す。保存しない・端末に出さない | 既定で、秘密がライブの画面に届かない。画面を人に見せても、値が出ない |
| D234 | ライブの画面は、アプリと同じ名前・別のポートで配る | 同じ名前なら、アプリの Cookie が枠の中でも送られる（名前が違うと、ログインが要るアプリが動かない）。ポートが違えば、アプリから、ライブの画面の中は読めない |
| D235 | 枠に入るのを拒むアプリは、別の窓で開く。応答のヘッダは書き換えない | 道具は、通信を変えない。見張りが道具の側にあるので、窓が分かれても、見えるものは同じ |
| D236 | まとめた図は、メモリの中だけに持ち、道具のサーバーが配る（出力先にファイルを書かない） | 見るだけの操作で、対象の repo にファイルを増やさない |
| D237 | 画面の箱に、任意の `meta.path`（画面のアドレスのパス）を書ける。無ければ、画面が 1 つならそれ、決まらなければ利用者が選ぶ | 「画面を開く」挙動と、開いている画面を結ぶ。箱 id の書き方に、意味を持たせない |
| D238 | 見張りは、新しいパッケージ（`packages/live`）に置き、CLI は、要るときだけ読みこむ | ブラウザを動かす部品に依るのは、ここだけにする。ビューアは、今までどおり schema と wiring だけに依る |
| D239 | 操作への区切り・時間の内訳・画面の変化の差・図との照合・値を伏せた形は、`@stack-atlas/wiring` の純粋な計算にする | ブラウザ無しでテストできる。ビューアと、見張りの両方から使える |
| D240 | ブラウザは、毎回、空の利用者の領域で開く。ログインの状態は持ちこさない | 持ちこすには、ログインの印（秘密）をファイルに残すことになる（Q40） |

## 8. ユーザーに確認すること

答えが無くても、推奨で進める（違えば直す）。

| # | 質問 | 推奨 |
|---|---|---|
| Q39 | 手元ではない宛先への通信を、どこまで止めるか。**(a) 書きこみだけ止める（読むだけの通信は通す）** / (b) 全部止める（外の字形・地図・ログインの画面なども出なくなる） | (a)。環境を汚さない、は守れる。(b) は、外から何かを読むアプリが動かなくなる |
| Q40 | ログインが要るアプリで、毎回ログインし直してよいか。**(a) 毎回ログインする（何も残さない）** / (b) ログインの状態を、手元のファイルに残して使い回す | (a)。(b) は、秘密を残すことになる。仕事の repo で不便なら、10-3 で考える |
| Q41 | 手元ではない宛先のログイン（外の認証の画面へ送信するもの）は、書きこみなので、止まる。それでよいか | よい（D207 のとおり）。仕事の環境は、手元で通せると聞いている。通せなければ、10-3 で相談する |

## 9. まだ確かめていないこと

- 利用者の仕事の環境で使っている、返事を差し替える仕組みそのもの（同じ形の小さなもので確かめた。10-3 で確かめる）
- つなぎっぱなしの通信・画面どうしを直接つなぐ通信を、道具の側から止められるか（10-2b で確かめ、止められない口は、開かせないか、§5.5 に書く）
- 画面を移る操作（1 つの操作の途中で、別の画面へ移るもの）の区切り
- 枠を拒むアプリの見分け（応答のヘッダの形が、いくつかある）
