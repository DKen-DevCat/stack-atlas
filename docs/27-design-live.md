# 27. 設計: ライブを製品にする（Phase 10-2）

作成: 2026-11-12。**状態: 設計レビュー（実装の前に 1 回。§10）を反映した版。10-2a（純粋な計算）は実装した（§11）。次は 10-2b。** 要件は docs/24、もとの設計は docs/25 §3.5（D206〜D209）、図の形は docs/26。決定の番号は **D228 から**、質問の番号は **Q39 から**。

## 1. 結論

試し（`prototype/live/`。ユーザーの了承済み）を、`stack-atlas live` という 1 つのコマンドにする。

- 人が、手元で起動した本物のアプリを操作する。道具は、**押した部品・ブラウザから出た通信・画面の変わった所**を見て、その部品から始まる挙動の経路を光らせる
- 見せ方は、試しと同じ: **記録してから再生する**（再生・一時停止、時間に比例した再生バー、見せる速さ 0.1〜1 倍。再生の操作の部品に文字は出さない）
- 試しから変える所は 3 つ:
  1. **通信は、ブラウザの外（道具の側）から見る**（試しは、アプリの中の通信の口を包んでいた）。アプリの動きに触らず、通信の口の種類を選ばない
  2. **手元の外へは、つながせない**（試しには無かった守り。D207）。読むことも、書くことも、ブラウザを起動する段で止める
  3. **通信の中身の値は、既定で出さない**（試しは、そのまま出していた）

## 2. 目的・やること・やらないこと・できたと言える条件

**目的**: 「ここを押すと、この流れで、こう画面に反映された」を、本物のアプリの上で追えるようにする（docs/24 の核。ユーザー、2026-11-11）。

**やること**

1. `stack-atlas live [<dir>] --url <手元の URL>`: 図（`<dir>/.stack-atlas/`）を検査し、道具がブラウザの窓を開く。左にアプリ、右に挙動の一覧と経路
2. 1 回の操作について、次の順に見せる: 押した部品 → 経路 → 実際に送ったもの → 実際に返ったもの → 画面の変わった所（足された・消された・文字が変わった。変わる前と、変わったあと）
3. 一覧から挙動を選ぶと、操作しなくても、その経路と、始まりの部品の場所が出る（docs/24 の核「挙動を選ぶと、経路が光る」）
4. 段ごとの、実際にかかった時間（時間の内訳）
5. 図に書かれた通信と、実際に出た通信の照合（合っている・図にあるが出なかった・図に無い）
6. 守り: 手元だけ・止めて見る・値を伏せる・保存しない（§5）

**やらないこと**（この段階では）

- 道具が、アプリを押すこと（操作するのは人だけ。確かめのための自動の操作は、テストの中だけ）
- 写しを使う入口（10-3b）、根拠・未読・古さの検査（10-1b）
- 通信・画面の記録を、ファイルに残すこと。共有すること
- 通信をわざと遅くすること（遅い回線のまね）
- ログインの状態を、次の回に持ちこすこと（Q40）
- 属性だけで変わる表示（色・出し入れを、要素の出入りや文字の変化なしに切り替えるもの）と、入力欄の中の値を、「画面の変わった所」として拾うこと（入力欄の値は、読まない。§5.3）

**できたと言える条件**

| # | 条件 | 確かめ方 |
|---|---|---|
| 1 | サンプルのアプリ（`prototype/live/app`）で、開く・投稿する・削除するの 3 つの挙動が、操作に合わせて選ばれ、経路・通信（メソッド・パス・状態）・画面の変わった所（増えた 1 件・消えた 1 件・件数の文字の変化）・時間の内訳（投稿の通信がいちばん長い）が出る。再生は、速さを変えて最後まで進み、再生バーで好きな所へ動かせ、止める・進めるが効き、再生の操作に文字が無い | ブラウザを動かすテスト |
| 2 | 図は、エージェントが書いたもの（`fixtures/atlas-live-agent`）を、手を入れずに使う。この図は、削除のボタンの部品が、一覧の部品の中にある（重なった部品）。削除を押すと、削除の挙動が選ばれる | 同上 |
| 3 | 手元の外へ、通信が 1 つも届かない。確かめる口: 読む・書く（画面が生きている間）、フォームの送信、手元宛ての通信が外へ回されたもの、画面を離れるとき・窓を閉じるときに送る通信、画面の裏で動く部品（共有のものを含む）からの通信、つなぎっぱなしの通信、返事を差し替える仕組みを素通りする通信。外の代わりには、この機械の、ループバックではないアドレスで聞く受け側と、どこにも解けない名前を使う（テストのための抜け道を、製品に作らない） | 受け側に届いた数を数えるテスト（0 件） |
| 4 | 「止めて見る」のあいだ、画面が生きている間の、手元宛ての書きこみが届かない。届きうる口（§5.2）は、文書と画面に出ている | 同上 |
| 5 | 値は、既定では出ない: 道具がライブの画面へ渡す出来事にも、端末の出力にも、通信の値が無い。「値を見る」を入れたあいだだけ、渡る。道具は、ファイルを書かない。ブラウザの利用者の領域は、終わるときに消える | 渡した出来事・端末の出力・書かれたファイルを調べるテスト |
| 6 | アプリの枠から、にせの合図を送っても、値は出ず、「止めて見る」は外れない | 枠の中から合図を送るテスト |
| 7 | 図・アプリから来た文字が、ライブの画面で HTML として解釈されない | 名前・文・パス・通信の中身・画面の文字に、タグの形の文字を入れたテスト |
| 8 | 枠に入るのを拒むアプリ（応答で拒む・上の窓を自分に移す）でも、別の窓で見られる | 拒む小さなサーバーでのテスト |
| 9 | 手元ではない `--url` は、開かずに断る（終了コード 2） | 単体テスト |
| 10 | 画面が 2 つある図で、開いている画面の「開く」挙動が選ばれる。始まりの合う挙動が無い操作は、通信が出たときだけ「図に無い操作」として出る | 単体テスト（区切りと選び方）と、画面が 2 つの小さな図 |
| 11 | 道具の中に、特定の言語やフレームワークを前提にした処理が無い（docs/24） | 新しい 3 つの置き場（§4.1）のコードに、手順書と同じ名前の一覧を掛けるテスト |

仕事の repo で使えること（docs/24 の条件 1・2）は、10-3 で確かめる。ここでは確かめない。

## 3. 全体像

```
stack-atlas live <dir> --url http://localhost:3000/
 │
 ├─ 図を読んで検査する（誤りがあれば、開かずに終わる）。まとめた図は、メモリの中だけに持つ
 ├─ 手元のサーバー（ループバックだけで聞く）: ライブの画面と、まとめた図を配る
 ├─ 行き先の無い中継（ループバックだけで聞く）: 手元の外へ行こうとした通信が、ここへ回されて、断られる
 └─ ブラウザ（道具が開く窓。毎回、空の利用者の領域。手元の外へは、つながらない）
      ├─ ライブの画面（ビューア）          ← 道具が、見た出来事を渡す
      │    ├─ 左の枠: 本物のアプリ（--url）
      │    └─ 右: 挙動の一覧・経路・再生・時間の内訳・画面の変わった所
      └─ 見張り（道具の側）
           ├─ 通信: ブラウザの外から見る（「止めて見る」のあいだは、止める）
           └─ 押した部品と、画面の変化: 枠の中の小さなスクリプトが見て、道具にだけ知らせる
```

出来事の流れは、一方向にする: **アプリ → 見張り（道具） → ライブの画面**。ライブの画面は、アプリの枠と直接は話さない。運ぶのは、ブラウザを動かす部品が持つ口だけで、手元のサーバーの通信では運ばない（同じ名前のアプリの枠や、ほかのタブから、送ったり読んだりできないようにする）。

## 4. 構造

### 4.1 置き場

| 場所 | 中身 | 依ってよいもの |
|---|---|---|
| `packages/wiring/src/live/` | 出来事の形（道具とライブの画面の間の約束）、操作への区切り、挙動の選び方、時間の内訳、画面の変化の差、図との照合、値を伏せた形。どれも純粋な計算 | `@stack-atlas/schema` |
| `packages/live/`（新しいパッケージ） | 見張り: ブラウザを開く、通信を見る・止める、枠の中のスクリプト、手元のサーバー、行き先の無い中継 | schema・wiring・core、ブラウザを動かす部品（ビューアの e2e・画面を撮る抽出器と同じもの。同じ版） |
| `packages/viewer/`（`live.html`・`src/live/`） | ライブの画面。`behaviorView` で経路を並べ、渡された出来事を再生する | schema・wiring だけ（今までどおり。core にも live にも依らない） |
| `packages/cli/src/commands/live.ts` | 引数を読み、図を検査し、見張りを起動する。見張りは、要るときだけ読みこむ | core・live |

ブラウザは、**1 種類に固定する**（ビューアの e2e と同じもの。D241）。守り（§5.2）を確かめたのは、この種類だけ。

### 4.2 見るもの

| 見るもの | どこで見るか | 理由 |
|---|---|---|
| ブラウザから出た通信（メソッド・パス・状態・時間・中身） | ブラウザの外（道具の側） | アプリの中の通信の口を包まない。通信の口の種類を選ばない。返事を差し替える仕組みが受けた通信の、送った中身・状態・返った中身・時間も取れる（試しとレビューで確かめた） |
| 押した・入力した・送信した要素が、図のどの部品か | アプリの枠の中の小さなスクリプト | 要素とセレクタの照らし合わせは、画面の中でしかできない |
| 画面の変わった所（足された・消された要素、変わった文字）と、部品の場所 | 同上 | 同上 |
| アプリの画面のアドレス（どの画面を開いているか） | ブラウザの外 | 枠の移動は、道具の側から見える |

**通信を見る仕組みは、見るだけにする。** 通信を途中で受け取る仕組み（止めるための仕組み）は、入れるだけで、キャッシュが効かなくなり、宛先の許しを確かめる事前の問い合わせに、道具が勝手に「許す」と答える（レビューで確かめた。ふだんは出ない通信が出る）。だから、止める仕組みは「止めて見る」のあいだだけ入れる（§5.2）。

- **数える通信**は、ブラウザが付ける通信の種類で選ぶ: アプリのスクリプトが出した通信と、フォームの送信。スクリプト・絵・字形・様式の読みこみは、数えない。特定の道具のパスの形で除くことは、しない（docs/24 §4）
- 返事を差し替える仕組みが素通しした通信は、外から 2 回見える（画面の側と、仕組みの側）。**画面の側の 1 回だけを数える**
- **時間は、ブラウザが測った値を使う**（道具に知らせが届いた時刻は、仕組みの有無で順が入れ替わる）

枠の中のスクリプトは、**見るだけ**: 何も押さない・通信を変えない・画面を変えない・アプリの持ち物（関数・変数）を置き換えない。

- 見たことは、ブラウザを動かす部品が用意する専用の口で、道具にだけ知らせる（窓どうしの知らせは使わない。試しは、宛先を選ばない知らせを使っていた）
- 図のセレクタは、要素とセレクタを照らす関数に渡すだけ。評価する文に埋めこまない。形のおかしいセレクタは、その部品だけ飛ばす
- **人の操作だけを拾う**（スクリプトが作った出来事は拾わない）。影の木の中で起きた出来事は、いちばん内側の要素から照らす
- 知らせの数と大きさに上限を置く（文字は長さ、列は数、頻度）。部品の場所は、開いたとき・画面が変わったとき・動かしたときに、まとめて知らせる（間引く）
- 画面の文字は、**見えている文字だけ**を拾う（隠れた要素・スクリプトや様式の中の文字は拾わない）。**入力欄の値は、読まない**

専用の口は、アプリの枠・アプリが作った枠・アプリが開いた別の窓の、どこからでも呼べる（レビューで確かめた）。道具は、次のように受ける。

| 知らせ・合図 | 受ける条件 |
|---|---|
| 見たことの知らせ（部品・画面の変化） | 呼んだ枠の出所が、アプリの出所（手元）であること。形と大きさを確かめる。変わるのは、ライブの画面の表示だけ |
| 切り替えの合図（値を見る・止めて見る） | **道具が開いたライブの画面のページの、いちばん上の枠で、出所がライブの画面**の 3 つがそろったときだけ |

### 4.3 操作への区切りと、再生（`packages/wiring/src/live/`）

**操作の始まり**

- 部品の出来事（押す・送信・入力・変更）か、画面を開いたこと
- **どの部品か**: 出来事の起きた要素に当たる部品を、**内側から順に全部**集める。そのうち、その種類の操作から始まる挙動を持つ、いちばん内側の部品を選ぶ（一覧の中の削除のボタンを押したとき、一覧ではなく、削除のボタンの部品になる）
- **1 回の手の動きは、1 つの操作**: 送信のボタンを押すと、「押す」と「送信」の 2 つの出来事が出る。短い間に続いた出来事は 1 つにまとめ、挙動を持つほうを採る。続けて打った入力も、1 つにまとめる
- 始まりの合う挙動が無く、通信も出なかった出来事は、操作として出さない。通信が出たときだけ、**図に無い操作**として、見えた通信を並べる

**操作の終わり**

- 数える通信がすべて済み、しばらく何も起きなくなったら、済んだとみなす
- **つなぎっぱなしの通信は、待たない**（開発用のサーバーは、たいてい 1 本持っている）。**長さに上限を置く**（上限で打ち切り、そこまでを見せる）。**次の操作が始まったら、前の操作を閉じる**

**どの挙動か**

- 始まり（部品と、操作の種類。開いたときは画面）が合う挙動
- 合う挙動が 2 つ以上あるとき（分岐で分かれるもの）は、実際に出た通信と、経路の通信の段が、いちばん多く合うものを選び、ほかも候補として出す

**時間の軸と、再生バー**

- 軸は、操作の始まりから、最後の画面の変化まで。再生は、この軸の上を進む
- 再生バーは、軸を、出来事の境目（送った・返った・画面が変わった）で切った帯。合計は、実際の時間と同じ（同時に出た通信を、足し合わせない）。帯の色は、そのとき待っている通信（いちばん先に出たもの）で決める
- 時間の内訳は、通信ごとの「送ってから返るまで」を並べる。同時に出た通信は重なるので、合計は軸の長さと合わないことがある、と出す

**画面の変化の差**: 一覧を丸ごと描き直すアプリでは、全部が「消えて、増えた」に見える。同じ中身の「消えた」と「増えた」を打ち消して、差だけを出す（試しで分かったこと）。文字だけの変化は、「変わる前 → 変わったあと」で出す。

**図との照合**

- 経路の段のうち、画面の側から受け口へ出る通信の段（`behaviorView` の `request`）と、実際の通信（メソッドとパス）を比べる
- パスの中の変わる部分は、**`{名前}` の形だけ**を、どの値とも合うとみなす（手順書が決めている書き方。ほかの書き方は読まない）。問い合わせの文字列は、比べない
- 比べ方: 図の通信の段 1 つにつき、合う実際の通信を 1 つ当てる。順番は問わない。結果は 3 つに分ける: 合っている・図にあるが出なかった・図に無い（図より多く出た分も、ここ）
- 食い違いは、検査の指摘と同じ書き方の文で出し、**写せる**ようにする（利用者が、エージェントに渡して図を直させる。道具は、ファイルに書かない）

経路のうち、実際に見えるのは、ブラウザから出る通信まで。その先（受け口からデータの置き場まで）は、図に書かれた段を出す。**実際に見えた段と、図に書かれただけの段は、見た目を分ける**（試しと同じ。実線と破線）。

### 4.4 ライブの画面（`packages/viewer`）

- 並びは、了承済みの試しと同じ: 左にアプリ、右に、挙動の一覧・経路（上から下へ）・再生の操作・時間の内訳・画面の変わった所。**アプリの画面の上に、道具の面（パネル）を重ねない**
- **一覧から挙動を選ぶ**と、操作していなくても、経路（すべて、図に書かれただけの段の見た目）と、始まりの部品の場所（線の枠）が出る。初めて見る人が、どこを押せばよいか分かる
- 再生の操作は部品だけ（文字を出さない。ユーザーの指定）: 再生・一時停止、再生バー（§4.3。いちばん長い帯は色を変える）、見せる速さのつまみ（0.1〜1 倍）
- 守りの部品 2 つは、**絵と、短い名前の両方**で出す（ユーザーの「文字はいらない」は、再生の操作についての指定。守りは、取り違えないことを先にする）:
  - **値を見る**（既定は切）: 入れているあいだ、通信の値が出る（§5.3）。入れているあいだ、色を変える
  - **止めて見る**: 入れているあいだ、手元宛ての書きこみを、出る直前で止める（§5.2）。起動のときに引数で入れた場合は、画面からは外せない
- アプリを開き直す部品（絵だけ）を、枠の上の細い帯に置く（枠の中のアプリには、ブラウザの読み直しが届かないため）
- 押した部品と、変わった所を囲む枠は、アプリの枠の上に線だけで描く（試しと同じ。前の操作の枠は残さない）。アプリが別の窓のとき（§4.5）は、囲む枠は出さず、右の一覧に名前で出す
- 図・アプリから来た文字（名前・文・パス・通信の中身・画面の文字）は、**すべて文字として出す**（HTML として組みこまない）
- 画面の状態は、アドレスの引数では変えない（アプリの URL も、道具が口で渡す）
- 画面の文言は日本語

### 4.5 アプリの置き方

- **既定は、ライブの画面の左の枠に入れる。** ライブの画面は、アプリと同じ名前（`localhost` など）の、別のポートで配る（D234）。名前が同じなので、アプリの Cookie は枠の中でも送られる。ポートが違うので、アプリの中のスクリプトから、ライブの画面の中は読めない
- **次のアプリは、別の窓で開く**（D235）。見張りは道具の側にあるので、見えるものは変わらない
  - 枠に入るのを、応答で拒むもの（通信の失敗と、枠のアドレスで見分けられる。レビューで確かめた）
  - 上の窓を、自分に移すもの（人が 1 度押したあとなら、移せる）。移されたら、ライブの画面を開き直して、別の窓に切り替える
  - 暗号つきで配っているもの（ライブの画面は暗号なしなので、枠の中では、アプリの Cookie がほとんど送られない。レビューで確かめた）
  - 利用者が、引数（`--window`）で選んだとき（自動の見分けが外れたときのため）
- 応答のヘッダを書き換えて枠に入れることは、しない（道具は、通信を変えない）
- 手元の、暗号つきのアプリの、証明書の誤りは、見逃す（手元の開発では、自分で作った証明書が多い。ブラウザは手元にしかつながらないので、見逃す範囲は手元だけ）
- アプリが、手元ではない所へ移ろうとしても、つながらない（§5.2）。つながらなかったと出す

### 4.6 図に足すもの: 画面のアドレス

「画面を開く」挙動と、いま開いている画面を結ぶために、**画面の箱に、任意の `meta.path`（その画面のアドレスのパス。例 `/articles/{id}`）**を書けるようにする（D237）。

- 無いとき: 画面の箱が 1 つなら、それとみなす。2 つ以上で決まらなければ、右の一覧で、利用者が画面を選ぶ
- 手順書（`harness/guide/`）に 1 行足す。契約 v0 のまま（任意の項目を足すだけ）。今ある図（画面が 1 つ）は、そのまま動く
- docs/25 D199 は、「URL を、エージェントに書かせない」と決めている（エージェントが書いた URL へ、道具がつなぎに行かないため）。`meta.path` は、**いまアプリが開いているアドレスと比べるだけ**に使い、道具がそこを開くことはない。開く URL は、毎回、人が `--url` で渡す。だから、D199 の守りは変わらない。人の持ち物（`atlas.yaml`）は、10-2 では読まない

## 5. 安全

守るもの: 共有の環境・本番（つながせない）、通信の中の秘密（出さない・残さない）、利用者の手元（図やアプリの文字に、道具を操らせない）。

### 5.1 信用しないもの

| もの | 扱い |
|---|---|
| 図（エージェントが書く） | 検査を通ったものだけ使う。セレクタは照らすだけ。名前・文は文字として出す。図の `request` と `meta.path` は、実際と**比べるだけ**に使う（道具が、図をもとに通信を送る・画面を開くことはない） |
| アプリ（の中のスクリプト） | 専用の口に、にせの知らせを送れる前提で作る。知らせで変わるのは、ライブの画面の表示だけ。道具の側の動き（何を止めるか・値を出すか）は、アプリからの知らせでは変わらない（§4.2 の表） |
| 通信・画面の中身 | 大きさに上限。文字として出す |

### 5.2 手元だけ（D207）

**「手元」とは**: ループバックのアドレスそのもの（`127.0.0.0/8`・`::1`）、`localhost`、`*.localhost`。**名前を解いた結果では、決めない**（道具が解いた結果と、ブラウザが実際につなぐ先は、別になりうる。レビューの指摘）。この機械の、ほかのアドレスは、手元に数えない。ほかの名前（開発用に決めた名前）は、利用者が引数（`--local-name <名前>`）で名指ししたときだけ、ブラウザの中でその名前をループバックに固定して、手元に数える（外へつなぐ抜け道には、ならない。固定した先は、ループバックだけ）。

**1 段め（いつも。切る手段は無い）: 手元の外へは、つながせない。**

- `--url` が手元でなければ、開かずに終わる（終了コード 2）
- ブラウザを起動する段で、**手元ではない宛先への通信を、すべて、行き先の無い中継に回す**（中継は、道具がループバックで聞き、何も中継せずに断る）。手元宛てだけが、直に出る。読むだけの通信も、外へは出ない
- 通信ごとに止める仕組みではないので、口の種類に依らない。2026-11-12 に、次の口で、外の代わりの受け側に 1 件も届かないことを確かめた（守りなしでは、同じ操作で 13 件届いた）: 読む・書く、フォームの送信、手元宛ての書きこみが外へ回されたもの、画面を離れるとき・窓を閉じるときに送る通信、画面の裏で動く共有の部品からの通信、つなぎっぱなしの通信。宛先を、アドレスそのもので書いても、名前で書いても同じ
- 外から何かを読むアプリ（外の字形・地図・外に置いたスクリプト・外の認証の画面）は、その部分が出ない・動かない。これは、D207（共有の環境には、ライブではつながない）のとおりの動き。読むだけなら通す、というゆるめ方は、ユーザーが決める（Q39）

**2 段め（「止めて見る」のあいだだけ）: 手元宛ての書きこみも止める。**

- 書きこむ通信（読むだけの通信ではないもの）を、出る直前で止め、送ろうとした中身の形を見せる。アプリからは、通信の失敗に見える
- 通信ごとに止める仕組みなので、**止められない口がある**: 画面を離れるとき・窓を閉じるときに送る通信、画面の裏で動く共有の部品からの通信、つなぎっぱなしの通信の中のやりとり（レビューで確かめた）。入れているあいだ、キャッシュが効かず、宛先の許しの事前の問い合わせは省かれる（§4.2）
- 漏れても、届く先は手元だけ（1 段めがある）。ユーザーは、手元への書きこみはよい、としている（D207）。だから、「止めて見る」は、**手元を汚しにくくする手伝い**であって、止めきる約束ではない。そのことを、画面の説明と、使い方に書く
- 返事を差し替える仕組みが、ブラウザの中で返事を作った通信は、もともと外へ出ない。「ブラウザの中で返事が作られた」と出す

### 5.3 秘密

通信の中身は、**道具の側で、値を伏せた形にしてから**、ライブの画面へ渡す。

| もの | 既定で渡すもの | 伏せるもの |
|---|---|---|
| 中身（キーと値の形のもの） | キーの名前（数に上限）と、値の型（文字・数・真偽・列の長さ） | 値 |
| 中身（フォームの形のもの） | 欄の名前 | 値 |
| 中身（そのほか: ただの文字・画面の形・ファイル） | 種類と大きさ | 中身の全部 |
| パス | 図の通信の段と合ったときは、図の書き方（`/items/{id}`）。合わないときは、値に見える部分（数字を含む・長い）を伏せた形 | パスの中の値 |
| 問い合わせの文字列 | キーの名前 | 値 |
| ヘッダ | 内容の種類だけ | ほかの全部（名前も） |
| 画面の変わった所 | 見えている文字（長さに上限） | 入力欄の値・隠れた要素（そもそも読まない） |

- **「値を見る」**を入れているあいだだけ、値（上限つき。ファイルの中身は出さない）を渡す。入れたときに表示している操作の分も、道具のメモリから渡す。次に起動したときは、切に戻る
- 値は、道具のメモリの中に、直近の操作の分だけ持つ。**ファイルに書かない。端末にも出さない**（端末に出すのは、起動の案内と、誤りだけ）
- ブラウザは、毎回、空の利用者の領域で開き、終わるときに消す（ふだんのブラウザの Cookie・保存したパスワードは、見えない）
- ライブの画面のサーバーには、アプリの Cookie も届く（Cookie は、ポートを区別しない。レビューで確かめた）。サーバーは、届いたヘッダを、使わない・記録しない

### 5.4 手元のサーバー

- ループバックだけで聞く。Host ヘッダが、手元の名前（§5.2 と同じ一覧）でなければ断る（今の `serve` と同じ守り）
- 配るのは、**ライブの画面の分だけ**（画面と、その資産、まとめた図）。ビューアのほかの画面・対象の repo の中のファイルは配らない
- ライブの画面には、読みこみ元を絞るヘッダを付ける（スクリプトは自分の出所だけ・枠はアプリの出所だけ・ほかの画面の枠には入らない）
- 行き先の無い中継も、ループバックだけで聞く。来たものを、どこにも中継しない

### 5.5 残る危なさ

| # | 危なさ | 扱い |
|---|---|---|
| 1 | 手元のバックエンドが、その先の共有の環境に書く | 道具からは見えない。「手元で起動した環境」は、その先も手元であること、と使い方に書く |
| 2 | 行き先の無い中継を通らない通信の口が、ほかにある（画面どうしを直接つなぐ通信など） | 確かめた口（§5.2）を、テストで固定する。画面どうしを直接つなぐ通信は、ブラウザの起動の段で、中継を通らないものを出させない設定にする。確かめていない口は、§9 に書く |
| 3 | 「止めて見る」が、止めきれない口を持つ | §5.2 のとおり、届く先は手元だけ。止めきる約束をしない |
| 4 | キーの名前・パス・画面の文字そのものが、秘密のことがある（宛名で引く表・招待の符号を出す画面） | キーの数に上限、パスの値に見える部分は伏せる。画面の文字は、左のアプリに出ているものと同じ。残る分は、使い方に書く |
| 5 | 「値を見る」を入れたまま、画面を人に見せる | 入れているあいだ、色を変える。次に起動したときは、切に戻る |

## 8. ユーザーに確認すること

| # | 質問 | いまの作り |
|---|---|---|
| Q39 | 外から何かを読むアプリ（外の字形・地図・外に置いたスクリプト・外の認証の画面）は、ライブでは、その部分が出ない・動かない。それでよいか。**(a) そのまま（外へは、読むことも書くこともさせない）** / (b) 読むだけの通信は、外へ通す | (a) で作る（D207 のとおり）。(b) は、共有の環境に、読みでつながる（Cookie や認証の印も付く）。書きこみだけを止める仕組みには、止められない口があることも分かっている（§10 高-1）。(b) にするかは、ユーザーが決める。答えがあるまで、(a) のまま |
| Q40 | ログインが要るアプリで、毎回ログインし直してよいか。**(a) 毎回ログインする（何も残さない）** / (b) ログインの状態を、手元のファイルに残して使い回す | (a) で作る。(b) は、秘密を残すことになる。仕事の repo で不便なら、10-3 で考える |

Q39 が (a) のとき、ログインを外の認証の画面に頼るアプリは、ライブではログインできない。仕事の環境は、手元で通せると聞いている（2026-11-11）。通せなければ、10-3 で相談する。

## 9. まだ確かめていないこと

- 利用者の仕事の環境で使っている、返事を差し替える仕組みそのもの（同じ形の小さなもので確かめた。10-3 で確かめる）
- 画面どうしを直接つなぐ通信・新しい運び方の通信・ブラウザが裏で送る報告が、行き先の無い中継を通るか（10-2b で確かめ、通らない口は、起動の設定で出させないか、§5.5 に書く）
- 窓を出したとき（確かめは、窓を出さない形で行った）の違い
- プロキシを使う環境（ブラウザの外に、もう 1 段の中継がある環境）での動き
- 影の木の中の部品（図のセレクタが、影の木の中まで届かない）
- 画面を移る操作（1 つの操作の途中で、別の画面へ移るもの）の区切り
- 受け口が 1 つだけの作り（どの通信も、同じメソッドとパス）では、図との照合が、ほとんど何も言えない
