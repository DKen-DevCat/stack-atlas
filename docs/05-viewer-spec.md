# 05. ビューア仕様

## 結論

プロトタイプ（`prototype/stack-atlas.html`）の挙動を仕様として書き起こしたもの。新しいビューアはこれと同等の体験を、graph.json だけを入力にして実現する。
ユーザーが特に評価したのは **データフローのアニメーション**、**キャッシュの可視化**、**画面内パーツのハイライト**。

## 画面構成

```
┌ トップバー ─────────────────────────────────────────────────────┐
│ タイトル │ [レイヤー展開|重ねる] [フローなし|閲覧MISS|閲覧HIT|入稿→反映] [⚡キャッシュ] [視点リセット] │
├──────────┬──────────────────────────────────────┬──────────────┤
│ 層チップ  │                                      │ 詳細パネル     │
│ L0 インフラ│            3D シーン                  │（選択時のみ）  │
│ L1 画面   │                                      │ スクショ差し替え│
│ L2 部品   │                                      │ キャッシュ表   │
│ L3 型     │                                      │ コード抜粋     │
├──────────┤          ［フロー進行表示］             │ 使っているもの │
│ 凡例      │                                      │ 使われている場所│
└──────────┴──────────────────────────────────────┴ メモ ─────────┘
```

スマホ（幅 760px 以下）: 凡例を隠し、パネルは下から出るシート（最大 58vh）、フロー進行表示は右上に移す。

## 3D シーン

- three.js r160、`OrbitControls`（ダンピングあり）、ラベルは `CSS2DRenderer`（HTML なのでくっきり表示され、クリックもできる）
- **層** = 半透明の板（41 × 20）＋層の色の外枠＋層名ラベル（板の右手前の角）
- **層の高さ**: `layer.y × (0.07 + 0.93 × explode)`。explode は 0（重ねる）〜 1（展開）で、目標値へ毎フレーム 12% ずつ寄せて動かす
- **ノードの形**（kind ごと）: infra 2.6×1.0×1.8、component 2.0×0.45×1.3、type 1.7×0.35×1.1 など（プロトタイプの `KIND` を参照）
- **画面ノード**: 板の上に立つスクリーン（幅 6.4、768:480 の比率）。下端を軸にして後ろへ傾ける。傾き = `-π/2 + explode × 1.05 rad`（重ねると平らに寝て、展開すると約 60° 起き上がる）。縁取りのフレームは状態に応じて色を変える
- **線の端点**: 画面ノードは、上の層とつながる線なら上端の中央、下の層とつながる線なら下端の中央から出す。それ以外のノードは中心から出す
- **同じ層の中の線**は、中央で 1.2 持ち上げた弧にする（板と重ならないように）

## ハイライト規則（最重要）

対象 a = ホバー中のノード、なければ選択中のノード。

**依存先 down(a)**:
1. a から出る `flow` エッジの先を 1 ホップだけ加える
2. a から `uses` / `deploy` / `http` / `schema` の向きにたどれるノードを、推移的にすべて加える

**影響範囲 up(a)**:
1. a に入る `flow` エッジの元を 1 ホップだけ加える
2. a へ `uses` / `deploy` / `http` の逆向きにたどれるノードを、推移的にすべて加える（`schema` はたどらない）

**表示**:
- a は選択色、down は赤、up は橙、それ以外は不透明度 0.12 まで薄くする（ラベルも 0.18）
- 赤くするエッジ: from が a か down に含まれ、to が down に含まれるもの。橙にするエッジ: to が a か up に含まれ、from が up に含まれるもの。それ以外の線は 0.05 まで薄くする
- **画面の中の領域**: `region.ref` が a なら塗り（赤 22%）＋太枠、down なら赤枠、up なら橙枠。コンポーネント名のタグはページごとに最初の 1 つの領域にだけ付ける
- 推移的にたどるので、型（例 `Race`）を指すと、それを使うすべての画面と Lambda までが影響範囲として光る。これは意図した挙動（変更の影響範囲を見るため）

**優先順位**: ハイライト ＞ フロー表示 ＞ キャッシュ表示 ＞ 通常。

## 操作

| 操作 | 挙動 |
|---|---|
| マウスでホバー（ノードかラベル） | ハイライト（離すと解除） |
| クリック／タップ | 選択してパネルを開く。何もない所をクリックすると解除 |
| 画面ノードの上でホバー／クリック | レイキャストの UV からスクショ上の座標を出し、`regions` に当たればそのコンポーネント、当たらなければ画面そのもの |
| ドラッグ | 回転。移動量が 6px を超えたらクリック扱いにしない |
| 右ドラッグ・ホイール・ピンチ | 移動・ズーム |
| パネルの関連チップ | そのノードを選択し、カメラを寄せる（700ms のイーズアウト） |
| 層チップ | その層の板・ノード・線の表示を切り替える |

## データフロー

- `flow.steps` の各ノードの位置（画面ノードは中心）を少し持ち上げた点列から `CatmullRomCurve3`（tension 0.15）を作る
- 粒子は 7 個（先頭が大きい）。`getPoint(t)` は区間ごとに等分されたパラメータなので、`round(t × (n−1))` で今のステップが分かる
- 1 ステップあたり 1.15 秒（HIT は 1.6 秒）。末尾で 1 秒止めてからループ
- 進行表示: 「4/14 /races/[id]: ISR キャッシュなし → ページを再生成」の形式
- フロー表示中（ハイライトがないとき）は、経路上のノードをシアン枠、それ以外を薄くする
- 層の explode が変わったら曲線を作り直す

## キャッシュモード

- `cache` を持つノードに、層の板の上で輪（tone の色、脈動）を描き、ラベルにバッジを出す
- `cache` を持たないノードは不透明度 0.3 まで薄くする
- パネルに `rules` の表と `note`（⚠）を出す

## パネル

上から: 種類・層、名前、ファイルパス、［画面ノードならスクショ欄］、［キャッシュ表］、コード抜粋、使っているもの（出ていくエッジ）、使われている場所（入ってくるエッジ）、メモ、「カメラを寄せる」ボタン。

## メモ

- 入力するたびに保存し、メモのあるノードのラベルに 📝 を付ける
- プロトタイプは localStorage。本実装は memos.json（未決事項 Q4）

## 規模が大きくなったときの対策（未実装・要検討）

- 層の板ごとにグループの島を折りたたむ（例: Lambda の中身を 1 つの箱にまとめる）
- フィルタ（ルート名、ディレクトリ、kind）
- 遠いときはラベルを間引く（LOD）
- ノードを `InstancedMesh` で描く

## 実装メモ（Phase 1 のビューアで意図して変えた点）

- three.js は npm 同梱の 0.187（プロトタイプは r160 を CDN から）。フォントはシステムフォント（Google Fonts を読まない）。
- **層の高さ**は層数 N から計算する: `((N−1)/2 − i) × 7.5`（4 層で 11.25 / 3.75 / −3.75 / −11.25。プロトタイプの手置き 11 / 3.5 / −3.5 / −10.5 とほぼ同じ）。
  板の大きさは自動レイアウトの結果（最小 41 × 20）。カメラの初期位置・距離・霧は板の大きさと層数に合わせて拡大する。
- **画面のテクスチャ**: プロトタイプのダミー描画はやめ、`screen.screenshot` を graph.json の URL 基準で遅延読み込みする。なければプレースホルダ（ルート名・kind 名・regions の点線枠と ref の名前）。
  regions の座標は `768 / screen.width` で一様に縮める（スクショを幅合わせで描くのと同じ縮尺）。ハイライトの重ね描きはハイライト対象か層の表示が変わったときだけ行う。
- **スクショの差し替え**（パネル）は「画像を差し替え／元に戻す」。localStorage に graph ごと・ノードごとに保存（`stack-atlas-shot:<project.name か graph の URL>:<id>`）。
- **メモ**の保存キーは `stack-atlas-memos:<project.name か graph の URL／ファイル名>`。プロトタイプにあった初期メモ（サンプル固有）は入れない。
- 層内の線の不透明度はプロトタイプの値（flow .6 / deploy .3 / uses .28 / http .5 / schema .35）。未知の kind は uses と同じ灰色。
- 追加: 検証結果の一覧（エラー赤・警告黄、閉じられる）、未知の `version` の警告（v1 として読める範囲で描画）、graph 未指定時の案内（ファイル選択・サンプル一覧）、トップバーの「開く」、Esc で選択解除、WebGL がないときのメッセージ。
- パネル: `code` がなければコード欄を出さない。`file` に `line` があれば `file:line` で出す。

## 配線図（graph.json v2。Phase 8-0b）

`version: 2` の graph.json（契約は `docs/16-graph-v2-contract.md`）を開くと、3D の地図ではなく **配線図**（SVG）で描く。v1 はこれまでどおり 3D の地図。
入口は `packages/viewer/src/main.ts`（`graph/load.ts` が `version` を見て `validateGraphV2` で検証し、エラーと警告を既存の一覧に出す）。配線図は WebGL を使わない。

- **規則はすべて `@stack-atlas/wiring`**（たどる・選ぶ・球の時刻・切れている線・レイアウト）。ビューアは描画と入力だけ（docs/16 D44）
- 操作と表示の規則は `docs/15-design-dataflow-model.md` §3.4b（分岐の表）・§3.5（たどる規則・球・項目の光り）・§3.6（表示の規則・レイアウト）。モック第 6 版（`prototype/dataflow-mock.html`）と同じ体験
- レイアウト: `layoutWiring(index)`（`packages/wiring/src/layout.ts`）。レーン（runtime。箱のあるレーンだけ）× 重心、項目は常に全部開き、口の中だけで相手側の並びに合わせて並べ替える、隙間と通り道の幅は線の数で決める、直交配線、host の枠、左に錨の無い成分を上に詰める。分岐を切り替えても箱は動かない。ELK と build 時の埋め込み（`position` / `route`）は後のフェーズ
- 球: 時刻は `schedule`（線の長さはレイアウトの経路の長さ）、描くのは `drawnBalls`（線ごとに 1 球）。親の項目に着いた時刻は子から出る線にも効く
- 切れている線: graph.json に書かれた `broken` を正にする（`brokenEnds`）。選択に関係なく赤の破線（warn は黄）で、受ける側の箱の手前で切れた端を描く

| モジュール（`packages/viewer/src/wiring/`） | 役目 |
|---|---|
| `app.ts` | 組み立て（索引 → レイアウト → 描画）、選択と分岐の状態、`window.__stackAtlas.wiring`（e2e・デバッグ用: `selection` / `lit` / `schedule` / `state` / `select()` / `setVariant()` / `seek()` / `setPaused()` / `ballPositions()`） |
| `render.ts` | SVG の文字列（DOM 無し・単体テスト可）。層の順はレーン → 沈んだ線 → host の枠 → 沈んだ箱 → 光る線 → 光る箱 → 球。文字は箱の幅に収める |
| `interaction.ts` | クリック（型 → 項目 → 光る線 → 箱 → 枠 → 空白）、hover（何も選んでいないときだけ）、Esc |
| `balls.ts` | 球、項目の光り（出発・到着、子は 60ms ずつ）、再生バー（▶/❚❚・シーク）と速さ（0.25〜4 倍） |
| `variantTable.ts` | 分岐の表（左「ない」・右「ある」。選択中でも hover で出る） |
| `canvas.ts` | 無限の平面（ドラッグ・ホイールで移動、ctrl/⌘ ＋ ホイールとピンチで拡大縮小、初期表示は全体） |

モックから変えた点: 丸い端の箱（actor・trigger）は楕円ではなく角丸（rx と ry を高さの半分に揃える）。光る host の枠は箱より下の層（中の沈んだ箱のクリックを奪わない）。項目の当たり判定は文字の下（型の文字をクリックできるように）。同じレーンの上の箱とつながる箱は「つながっている箱のすぐ下」（docs/15 §8 #13 どおり。モックは直前の箱の下）。
