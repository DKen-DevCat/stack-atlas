# 28. 設計: 根拠・未読・古さの検査（Phase 10-1b）

作成: 2026-11-13。**状態: 下書き。設計レビュー（実装の前に 1 回。§9）の前。** 要件は docs/24、もとの設計は docs/25 §3.1・§3.4（D199・D201・D202・D204）、図の形は docs/26（契約 v0）。決定の番号は **D247 から**、質問の番号は **Q41 から**。

## 1. 結論

`stack-atlas check` に、3 つの検査を足す。どれも、対象のコードの意味は読まず、**文字列とパスとハッシュだけ**を見る（言語を選ばない）。

| 検査 | 見ること | 結果の重さ |
|---|---|---|
| 根拠 | 箱と線に書いた「どのファイルの、どの行のあたりに、どんな文字列があるか」が、本当にそこにあるか | 無ければ誤り |
| 未読 | 対象の repo が追跡しているファイルのうち、どの根拠にも、読んだという申告にも出てこないもの | 知らせだけ（関門にしない。D204） |
| 古さ | 受け入れたとき（`check --accept`）から、根拠の中身が変わったか | 警告（変わった箱と線だけを、エージェントが読み直す） |

**根拠の検査が言えるのは「その場所を見た」まで。** 線の意味が正しいことは言えない（docs/25 D201）。

## 2. 目的・やること・やらないこと・できたと言える条件

**目的**: エージェントが書いた図の、**どこが本当にコードを見て書かれたか**・**どこを読んでいないか**・**コードが変わってどこが古くなったか**を、道具が言語を知らずに示す。古くなった所だけを、エージェントに読み直させる（図を作り直さない）。

**やること**

1. 契約に、箱と線の根拠（`evidence`）を足す（任意の項目。契約 v0 のまま）
2. `reading.yaml`（エージェントの申告: 読んだが箱にしなかった所・読まなかった所と、その理由）を読む
3. `atlas.yaml`（人の持ち物: repo の名前と場所の表）を読む。複数の repo の図で、根拠のパスを repo ごとに解く
4. `state/fingerprints.json`（道具の持ち物: 根拠の指紋）を、`check --accept` が書く。`check` は、いまの中身と比べる
5. 手順書を 0.4 版にする（根拠と `reading.yaml` の書き方）

**やらないこと**

- 線の意味が正しいかを確かめること（言語を知らないと、できない）
- capture（画面の写し）と、その記録の段（10-3b）
- `atlas.yaml` の画面の URL・状態（capture の段で読む）
- 未読を関門にすること（D204）

**できたと言える条件**

| # | 条件 | 確かめ方 |
|---|---|---|
| 1 | 正解の図（`fixtures/atlas-live`）と、エージェントが書いた図（`fixtures/atlas-live-agent`）に根拠を足したものが、サンプルのアプリに対して、根拠の誤り 0 で通る | テスト |
| 2 | 根拠の文字列が無い・ファイルが無い・行の範囲が外れている・短すぎる文字列は、誤りになる | テスト（わざと入れた誤り） |
| 3 | 未読が、最上位のディレクトリごとの数と割合で出る。`reading.yaml` で申告したもの・repo の無視の設定にあるものは、数えない | テスト |
| 4 | `check --accept` のあと、根拠の行の上に 1 行足しただけでは「古い」にならない（中身で探し直す）。根拠の中身を変えると「古い」になる。範囲の外だけ変えると「要確認」になる | テスト |
| 5 | 道具は、対象の repo の外・シンボリックリンク・秘密らしいファイルを読まない。根拠のファイルの中身を、出力に写さない | テスト |
| 6 | 道具の中に、特定の言語やフレームワークを前提にした処理が無い | 名前の一覧を掛けるテスト |
| 7 | 対象の repo の設定で、道具がコマンドを実行させられない | テスト（§5 の守り） |

## 3. 書く形

### 3.1 根拠（`evidence`。エージェントが書く）

箱と線に、任意で書ける。どちらも、1 つか、列。

```yaml
nodes:
  - id: "fn:load"
    file: app/index.html     # 今までどおり（箱の主な場所）
    line: 78
    evidence:
      - { file: app/index.html, lines: [78, 92], text: "async function load()" }
wires:
  - from: "fn:load#out/request"
    to: "endpoint:GET /api/comments#in/request"
    via: http
    evidence: { file: app/index.html, lines: [80, 80], text: "api('/comments')" }
```

- `file`: 図の置き場からの相対パス（1 つの repo）。複数の repo のときは `<repo の名前>/<repo からの相対パス>`（`atlas.yaml` の表で解く）
- `lines`: 行の範囲（1 から。両端を含む）。**探す範囲の目安**で、厳密な位置ではない（§4.2）
- `text`: その範囲に**そのまま書いてある**文字列（空白の連なりは 1 つとみなす）。8 文字以上で、英字・数字・かなのどれかを含むこと（記号だけ・短い字句は、どこにでもあるので、見た証にならない）
- 箱の `evidence` が無ければ、`file`・`line` を、文字列の無い根拠とみなす（ファイルがあることだけを確かめる）。手順書は、`evidence` を書くよう求める
- 線の `evidence` が無ければ、線の根拠は「無い」（警告。docs/25 D201）

### 3.2 `reading.yaml`（エージェントが書く）

```yaml
read:        # 読んだが、箱にも線にもしなかったもの
  - { path: app/sw.js, why: "LATENCY と sleep は、経路の上に無い" }
skipped:     # 読まなかったもの
  - { path: docs/, why: "文書。アプリの動きではない" }
  - { path: "assets/*.png", why: "画像" }
```

- `path` は、ファイルか、ディレクトリ（末尾の `/`）か、`*`（1 段の中だけ）を使う形。**全部を指す書き方（`*`・`**`・`/`・空）は受け付けない**（docs/25 §3.4）
- `why` は必須（空は誤り）

### 3.3 `atlas.yaml`（人が書く。エージェントは書かない。D199）

```yaml
repos:
  - { name: web, path: ../web }        # 図の置き場（.stack-atlas/ の親）からの相対パス
  - { name: platform, path: ../platform }
```

- 無ければ、図の置き場そのものが、1 つの repo
- `path` は、図の置き場からの相対。図の置き場の外を指してよい（複数の repo を束ねるディレクトリ。docs/25 Q37）。ただし、道具が読むのは、表に書いた repo の中だけ

### 3.4 `state/fingerprints.json`（道具が書く。エージェントは書かない）

```json
{
  "version": 1,
  "accepted": "2026-11-13T10:00:00Z",
  "evidence": {
    "node:fn:load#0": { "file": "app/index.html", "lines": [78, 92], "range": "<sha256>", "whole": "<sha256>" }
  }
}
```

- キーは「箱か線の名指し」と、根拠の番号
- `range`: 根拠を見つけた行の範囲の中身（空白の連なりを 1 つにしたもの）の指紋。`whole`: ファイル全体の指紋
- `check --accept` だけが書く。`check` は読むだけ

## 4. 検査

### 4.1 根拠

1. `file` を、repo の中のパスに解く。repo の外・シンボリックリンク・無いファイル・大きすぎるファイル・**秘密らしいファイル**（§5）は、誤り（中身は読まない）
2. `text` を、`lines` の範囲で探す。無ければ、**範囲の前後に広げて**探す（上下に 200 行まで）。それでも無ければ、ファイル全体で探す
   - 範囲で見つかった: 通る
   - 広げて見つかった: 通る。「行がずれている」を知らせとして出す（`check --accept` で直る）
   - ファイルのほかの所でだけ見つかった: 警告（「書いた行の範囲から遠い」）
   - どこにも無い: 誤り（「その文字列は、そのファイルに無い」）
3. 出力には、ファイル名・行・**エージェントが書いた文字列**だけを出す。ファイルの中身は写さない

### 4.2 古さ（D202）

`state/fingerprints.json` があるときだけ見る。根拠ごとに:

1. 4.1 で見つけた範囲（中身で探し直した、いまの位置）の指紋を作る
2. 受け入れたときの `range` と同じ → 古くない。行の番号がずれていても、古くない
3. 違う → **古い**（警告。「変わった箱と線」として名指し）
4. `range` は同じだが、ファイル全体の `whole` が違う → **要確認**（知らせ。範囲の外が変わった）
5. 受け入れたときに無かった根拠 → 「まだ受け入れていない」（知らせ）

`check --accept` は、誤りが 0 のときだけ、いまの指紋を書く（誤りのある図を受け入れない）。書く前に、変わる根拠の数を出す。

### 4.3 未読（D204）

1. 対象の repo が追跡しているファイルの一覧を得る（§5 の守りの下で、`git ls-files`）。git の repo でなければ、未読は出さない（知らせだけ）
2. 次のものを除く: どれかの根拠の `file`（箱の `file` を含む）・`reading.yaml` の `read` と `skipped`
3. 残りを、**最上位のディレクトリごとに、数と割合**で出す。ファイルの名前の一覧は、`--json` でだけ出す（数に上限）
4. 誤りにも警告にもしない（知らせ）。言語やファイルの種類の表は持たない（docs/24 §3 の条件 3）

### 4.4 出力

- 検査の種類に、`evidence`（根拠）・`stale`（古さ）・`unread`（未読）を足す。重さに、今の誤り・警告に加えて、**知らせ**（`info`）を足す。知らせは、終了コードを変えない
- 人が読む形の最後に、未読の要約（最上位のディレクトリごとの数と割合）を出す
- `--json` は、今の形に、`unread` の要約と、古い根拠の一覧を足す

## 5. 安全

対象の repo は、信用しない（エージェントが読む repo で、図もエージェントが書く）。

| 危なさ | 守り |
|---|---|
| 根拠のパスで、repo の外・秘密を読ませる | 今の読みの守り（`local-files.ts`: repo の中に閉じる・リンクを辿らない・大きさの上限）を通す。**秘密らしいファイル**（名前が `.env` で始まる・`.pem`・`.key`・`id_rsa` など。今の手順書が開くなと言っているもの）は、読まずに誤りにする |
| 根拠の中身を、出力に写す | 出力に出すのは、エージェントが書いた文字列だけ。見つかったかどうかと、行の番号だけを足す |
| `git ls-files` で、repo の設定にコマンドを実行させられる（`core.fsmonitor` など） | git は、設定で外から何かを実行させる口を閉じて呼ぶ: `-c core.fsmonitor=false -c core.hooksPath=<空>`、ページャを使わない、シェルを通さない（引数の列で呼ぶ）。全体の設定・利用者の設定を読まない（`GIT_CONFIG_NOSYSTEM=1`・`GIT_CONFIG_GLOBAL=<空>`）。ネットワークを使う操作はしない |
| `atlas.yaml` の repo のパスで、どこでも読ませる | `atlas.yaml` は人の持ち物（エージェントは書かない約束。手順書が禁じる）。それでも、表の repo は、ディレクトリで、シンボリックリンクでないこと。根拠は、その repo の中だけ |
| 指紋のファイルを、エージェントが書き換える | `state/` は道具の持ち物。手順書が書くことを禁じる。check は、指紋のファイルの形が合わなければ、無いものとして扱う（古さを出さない）と知らせる |

## 6. 段取り

設計レビュー（1 回）のあと、1 つの PR で作る。

1. 契約: `evidence` を箱と線に足す（schema・型・docs/16・docs/26）
2. core: `atlas.yaml`・`reading.yaml`・根拠の検査・指紋・未読（`packages/core/src/atlas/`）
3. CLI: `check --accept`
4. 手順書 0.4 版と例。正解の図とエージェントの図に根拠を足す（手で。サンプルのアプリの行を見て書く）
5. テスト（条件 1〜7）

## 7. 決めたこと

| # | 決定 | 理由 |
|---|---|---|
| D247 | 根拠は「ファイル・行の範囲・そこにある文字列」。行の範囲は探す目安で、見つからなければ広げて探す | 行の番号は、すぐずれる。文字列があれば、中身で探し直せる（D202） |
| D248 | 根拠の文字列は 8 文字以上で、英字・数字・かなのどれかを含む | 記号だけ・短い字句は、どのファイルにもあるので、見た証にならない |
| D249 | 根拠が見つからないのは誤り。遠い所でだけ見つかるのは警告。行がずれているのは知らせ | 無い文字列を書いたのは、見ていない（作り話の）しるし。ずれは、`--accept` で直る |
| D250 | 未読は知らせで、最上位のディレクトリごとの数と割合。言語やファイルの種類の表を持たない | D204。docs/24 §3 の条件 3 |
| D251 | 指紋は、見つけた範囲の中身（空白を正規化）と、ファイル全体の 2 段。`check --accept` だけが書く。誤りがあれば受け入れない | D199・D202 |
| D252 | git は、設定で外から何かを実行させる口を閉じて、追跡しているファイルの一覧を得るためだけに呼ぶ | 対象の repo の設定は信用しない |
| D253 | 秘密らしいファイルは、根拠に書かれても読まない（誤り） | 手順書は、エージェントに開くなと言っている。道具も読まない |
| D254 | 契約に足す `evidence` は任意の項目。契約 v0 のまま | 今ある図は、そのまま通る（線の根拠が無いと警告が出る） |
