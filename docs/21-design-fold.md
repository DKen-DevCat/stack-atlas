# 21. 設計: 配線図をまとめて畳む（Phase 8-8、Q19）

作成: 2026-11-10。**状態: 設計を確定。8-8a（wiring）は実装済み（§11）、8-8b（ビューア）は 8-7 のマージ後。** 独立の設計レビュー 1 回（§10）と、捨てるコードでのスパイク 2 つ（§5.3・§5.4）を反映した。Q19 の決定（2026-11-10「ok です、mock なしで行きましょう」= 畳む ＋ 入れ子のレイアウト）を受けた設計だが、**入れ子のレイアウトは測った結果、作らないことを勧める**（§2.6・§5.3。ユーザーの確認は §6 の Q19-d）。8-7（docs/18 §11: 場面ごとに DOM を 1 回作り、選択は付け替える）が先に入っている前提。決定の番号は **D123 から**（D114〜D122 は 8-7。docs/18 §11.11）。

困っていること: 実リポジトリ（箱 310・枠 6・線 1979）を開くと、配置が 28508×16858 になり、全体を入れる倍率は 0.049（2 面の半分の幅では 0.024）。箱の名前は 0.6px で、全体が見えない。

## 1. 結論

- **畳む単位は「包含の木の切り口」**にする。木は 根 > ディレクトリの段 > group > 箱。開いている入れ物の集合（切り口）が、今見えているものを決める。`@stack-atlas/wiring` の関数は木（親の対応）と置き場（箱 → host・レーン）を引数に取り、`group × runtime` を書き込まない（Phase 9 で木が graph に入ったら、木の作り方だけ差し替える）
- **地図の単位（group × runtime）で畳むだけでは足りない**（実測）。実リポジトリは 310 → 143 箱で倍率 0.19、名前は 2.3px。ディレクトリの段まで畳むと 18 箱・倍率 0.70、名前は 11px（畳んだ箱の名前は 16px）になる
- **箱が 100 以下の graph は今のまま**（畳まない。fixture-poly の見た目も既存の e2e も変わらない）。100 を超えたら、開いた直後は「根から 1 段ずつ、見える単位が 24 以下の間だけ開いた」切り口にする（見える単位が 4 未満なら、24 を超えてももう 1 段開く）
- **畳んだ箱**は、名前の帯と口 1 行（`in/_`・`out/_`）だけの小さい箱。クリックは選択、開くのは `▸`・ダブルクリック・Enter。**選んでも勝手には開かない**（経路を全部開くと実リポジトリで 310 箱中 260 箱が見えてしまう。実測）
- **線は「見えている端の対 × 行き / 戻り」ごとに 1 本**。両端の箱が開いていれば今と同じ項目から項目への線、片方が畳まれていれば畳んだ箱の口へ集まる
- **開く = その切り口の graph を、今の `layoutWiring` でそのまま配置し直す**。入れ子のレイアウト（枠の中に子を置き、外の順を凍らせる）は作らない。スパイクで作って測ったら、先に決めた基準のうち「大きさ」と「交差」を fixture-poly と実リポジトリで満たさず、実リポジトリの開いた直後の倍率が 0.70 → 0.36 に落ちた（§5.3）。配置の中核（`packages/wiring/src/layout/`）は 1 行も変えない
- 枠が無い代わりに 3 つ入れる: (1) 開いた入れ物の中の単位の左上に **`▾ <入れ物の名前>`**（畳み直す・入れ物を選ぶ）、(2) 開閉しても、操作した単位は画面の同じ位置に留める、(3) 新しく現れた単位の縁を 1 回だけ光らせる
- **たどる規則は全体の graph のまま**（切り口を変えても、光る箱と線の集合は同じ）。**球の時刻は、見えている線の長さで作り直す**（畳むと周期が短くなる。再生位置は周期に対する割合で引き継ぐ）。地図では、球の載る束と向きは変わらないが、球の数は変わることがある（スパイク 2。§5.4）
- **段取り**: スパイク（済）→ 8-8a（wiring だけ。8-7 と並行できる）→ 8-8b（ビューア。8-7 のマージ後。ここで実リポジトリの全体が見える）。8-8c（入れ子のレイアウト）は見送り

## 2. 構造

### 2.1 包含の木と切り口

```
根
├─ <repo>/                    ディレクトリの段（複数 repo では最初の段が repo）
│   ├─ <dir>/…                子が 1 つだけの段はつぶして 1 つにする（`a/b/c`）
│   │   ├─ group              中の箱が 2 つ以上の group
│   │   │   ├─ 箱
│   │   │   └─ 箱
│   │   └─ 箱                 group の無い箱、1 箱だけの group の箱
│   └─ …
└─ 箱                         file の無い箱（利用者など）は根の直下
```

- **木の形（wiring の型）**: `Containment { containers: Map<id, Container>, parentOfBox: Map<箱の id, 入れ物の id> }`、`Container { id, name, kind, parent?, memo? }`。`kind` は開いた文字列（8-8 が作るのは `'dir'` と `'group'`。Phase 9 で種類が増えても型を変えない）。`memo` はメモのキー（あれば、その入れ物にメモを書ける）。JSON にできる・決定的。畳む・写す関数は、この形だけを見る
- **8-8 での木の作り方** `containmentOf(graph)`: 箱の `file`（group は `groups[].file`、無ければ中の箱の共通のディレクトリ）からディレクトリの段を作り、`group` に箱が 2 つ以上あれば group の入れ物にする。**この関数だけが Phase 9 で捨てるもの**（§7）
  - 入れ物の id は名前空間を分ける: ディレクトリは `d:<パス>`、group は `g:<group の値>`（group の値が `d:` で始まっても重ならない）。箱・host の id と同じになったら、重ならなくなるまで末尾に `~` を足す（`?sel=` が箱と入れ物を取り違えないように）
  - group の入れ物の `memo` は **group の値そのもの**（今のメモのキー）。地図のノードの id（`group:` の付いたもの・`@runtime` の写し）は使わない。ディレクトリの入れ物に `memo` は無い（書けない）
  - host の枠は木に入れない（今までどおり枠として描く）
- **敵対的な入力**（8-6 の地図と同じ型の入力を、同じ考えで受ける）
  - ディレクトリの段は 32 まで（それより深い所は 32 段目の入れ物に入れる）。id を作るのは、子が 1 つの段をつぶした**あと**の入れ物だけ（段ごとに接頭の文字列を作らない。64,000 段のパスでも段の数に比例）
  - 木をたどる関数は再帰しない（深さでスタックが尽きない）。祖先をたどるときは訪問済みの集合を持つ
  - 表示名は地図と同じ上限（`NAME_MAX_LENGTH` = 120。長ければ頭を落とす）
  - 木は Phase 9 で graph.json から来る。`foldView` などの入口で `cleanContainment` を通す: 無い親・親の循環は、その入れ物を根の直下に付け直す。id はすべて `Map` のキーとして持つ（`__proto__` などをオブジェクトのキーにしない）
  - 入れ物の名前・id を DOM に書くときは今の `esc`、セレクタに入れるときは `CSS.escape`（単位の id は下の形なので、入れ物の id・パスはセレクタに入らない）
- **切り口** = 開いている入れ物の集合。祖先が全部開いている入れ物・箱が「見えている」。見えていて閉じている入れ物が**畳んだ箱**。開いている入れ物は枠を描かない（中の単位の左上に名前が出る。§2.2）
  - **正規の形**: 切り口が持つのは「祖先が全部開いている入れ物」だけ。入れ物を畳むと、その下で開いていたものは忘れる（開き直すと 1 段だけ開く）。URL と状態が 1 対 1 になる
- **置き場で割る**: 1 つの入れ物の中に、別のレーン・別の host の箱が混ざることがある（実リポジトリで host が混ざる group が 5）。畳んだ箱は「入れ物 × 置き場」ごとに 1 つ描く。レーンと host の枠の規則（8-3a）を壊さないため。開閉は入れ物ごと（割ったものは一緒に開閉する）
  - 置き場は `foldView` の引数（箱 → 置き場のキー）。8-8 の既定 `slicesOf(index)` は「host があれば host、無ければレーン」。Phase 9 で置き場の決め方が変わっても `foldView` は変えない
  - 割るので、**同じ名前の畳んだ箱が置き場ごとに並ぶ**。実リポジトリの初めの切り口は、6 つの入れ物が割れて畳んだ箱 17 個（1 つの入れ物から最大 5 個。host の枠の中に 11 個）＋ 箱 1 個。合成 300 箱は、根の直下の 1 つの入れ物が 14 個（host 12 ＋ レーン 2）に割れる。どれがどれかは host の枠とレーンで見分ける（「この Lambda に載っている、このディレクトリのコード」）
  - 割った結果、中が 1 箱だけになっても畳んだ箱のまま描く（規則を 1 つにする。初めの切り口で実リポジトリ 2 個、fixture-poly 4 個）
- **単位の id**（畳んだ箱の、畳んだ graph の中での箱の id）: `fold:<入れ物の通し番号>:<置き場の通し番号>`。番号は木と置き場の宣言の順から決まり、切り口に依らない（開閉しても、同じ畳んだ箱は同じ id）。入れ物の id・パス・group の値は含めない（ref・属性・セレクタに入る文字を選べる）。実在の箱・host の id と同じになったら、重ならなくなるまで末尾に `~` を足す

### 2.2 見える単位と線

- **畳んだ箱の形**: 名前の帯（高さ 26）と口 1 行。左の辺に `in/_`、右の辺に `out/_`（項目が `_` 1 つだけの口は今もある形。fixture-poly では 28 箱が持つ）。幅 200（ふつうの箱は 300。今ある `layoutWiring` の引数 `widthOf` で渡す）、名前は 16px（ふつうは 12px）。長い名前は**頭を切って** `…/src/lib` のようにし（パスは末尾が見分けに効く）、`<title>` に全部
- **ふつうの箱との見分け**（D31: 凡例・バッジ無し）: **重ねた札の形**（同じ形を右下に 4px ずらして背面に 1 枚）。二重の縁にはしない（endpoint の形と同じになる）。箱の外の左上の「種類」の位置に `フォルダ · 27` / `lib · 5`（入れ物の種類と中の箱の数。D31 の例外の場所をそのまま使う）。名前の帯の左端に `▸`（操作の部品）
- **開いた入れ物**: 枠は描かない。その中の単位（箱・畳んだ箱）の左上の「種類」の前に、**いちばん内側の開いた入れ物の名前**を `▾ <名前>` で出す（頭を切る。`<title>` に根からの道を全部）。`▾` はその入れ物を畳む、名前はその入れ物を選ぶ（中の箱が全部光る = どこまでが同じ入れ物かが見える）。根の直下の単位と、平らな表示（§2.5）には出ない
- **線**: 全体の線 w の両端を「見えている端」に写す。端の箱が見えていればその項目、畳まれていれば畳んだ箱の口。両端が同じ畳んだ箱の中に入った線は描かない（球は脈動。§2.3）
  - **束の単位は（from の端, to の端, 戻りか）**。両端の箱が見えている線は、今と同じ 1 本ずつ（同じ端の対に行きと戻りがあれば今と同じ 2 本）。片方でも畳まれていれば、同じ単位の線は 1 本
  - 束の `via`: 束の中の「向きを決める線」（今の `isForward`）のうち、graph の宣言の順で最初の線のもの。向きを決める線が無ければ最初の線のもの（束に呼び出しが 1 本でも入っていれば、層を決める線として働く）
  - 束かどうかの見分けは付けない（線の太さは今「沈んだ線 / 光る線」の区別に使っている。束になるのは畳んだ箱の口に出入りする線だけなので、形で分かる）
  - 開いた箱どうしは、今と同じ項目から項目への線（「I/O は常に全部開いておく」「束の線は分かりにくい」への答え: 束になるのは畳んだ所だけ）
- **線のキー**: `foldView` は、見えている単位と線を v2 の graph の形で作り、**自分の索引**（`indexGraph(畳んだ graph)`）を持って返す。線のキーは今の規則（`graph.wires` の添字）で振り直されるので、全体の線のキーと同じとは仮定しない。`foldView` が「全体の線のキー → 見えている線のキー（か、単位の中）」の表とその逆を返し、光るもの・球・差分・分岐はこの表を通す
  - 全部開いた切り口では、畳んだ graph は箱・線の順まで元の graph と同じになる（配置も平らな配置と同じ。テストで固定する）
- **切れている線**（赤は常に見える）
  - 見えている線に、中の線の `broken` を持たせる（束は path ごとに 1 つ。error があれば error）。端の決め方は今の `brokenEnds` のまま: 見えている箱では項目へ降り、畳んだ箱では `_` で止まる。配置のコードは変えずに、今と同じ赤い破線と切れた端が出る
  - 両端が同じ畳んだ箱の中に入った切れた線: その畳んだ箱の `out/_` の口に、赤い切れた端を 1 つ出す（中に error があれば error の色。`<title>` に件数）。既定の表示で error が見えなくなることは無い
- **メモ・差分・警告・分岐の集約**（どれもバッジを足さない）
  - メモ: `memo` のある入れ物（group）の畳んだ箱は、group か中の箱にメモがあれば右下の角を折る。札のキーは `memo`。ディレクトリの入れ物にはメモを書けない
  - 差分（`?prev=`）: 木と `foldView` は**描く索引**（幽霊を足した graph。今の `planDraw` の `drawIndex`）から作り、選択は今の graph の索引でたどる（今と同じ分け方）。幽霊の箱も `file`・`group` で木に入る。畳んだ箱の色は、中が全部追加なら追加の縁、全部幽霊なら幽霊の形、それ以外で中に追加・変更・幽霊が 1 つでもあれば変更の縁（開くと中身が分かる）。「100 を超えるか」は今の graph の箱で数える（`?prev=` を付けただけで畳んだ表示に変わらない）
  - 警告（題名の横のリンク。D64）: 一覧から箱を選ぶと、§2.4 の規則で見えている祖先に輪が出る
  - 分岐（variants）: 束の中の線が全部止まっていれば束も止まった線にする

### 2.3 たどる・光らせる・球

- **選択**: `select(index, state, selection)` は全体の graph の索引のまま。切り口を変えても、光る箱・項目・線の集合は変わらない
- **光るものを写す**: `litOn(view, lit)` → 畳んだ索引の語彙での光るもの（光る単位・見えている項目・見えている線の区間・始点）。見えている箱の中の区間（口から口）はそのまま、畳んだ箱の中の区間は無い。何も畳んでいなければ元と同じ
- **球の時刻**（レビューの H1。今の時刻は配置の経路長で決まるので「全体の graph のまま」にはできない）
  - **線の時間 = その線が写る、見えている線の経路長 / 速さ**。単位の中に入って見えない線は **0.25 秒**（箱の中を通る時間 `INNER` と同じ定数。0 にすると地図の球が消える）。箱の中の区間は今のまま
  - 切り口が変わるたびに、`schedule` をこの時間で作り直す（`foldLengths(view, layout)` を `schedule` の `lengthOf` に渡す）。全体の平らな配置（160〜580ms）は計算しない
  - 開閉したとき、再生位置は**周期に対する割合**で引き継ぐ（速さを変えたときと同じ `rescaleTime`。8-7 の `setScene` の規則）
- **開閉で保たれるもの・変わるもの**（スパイク 2。fixture-poly の 67 通りの選択 × 13 通りの切り口。§5.4）

  | | |
  |---|---|
  | 保たれる | 選択（光る集合）、再生バーの割合（誤差 1e-16。400 回開閉してもずれない）、球になる線の集合、地図で球の載る束と向き・脈動の数（871 / 871 通り） |
  | 変わる | 周期（`route:/` で 54.8 秒 → 全部畳むと 14.9 秒、上限 24 の切り口で 19.0 秒）、同じ線の球が周回のどこで出るか（割合で中央 0.12〜0.14、最大 0.40）、**地図の球の数**（871 通り中 88 通りで違う。差は中央 1・最大 6。`route:/` は 13 通りとも 21 のまま） |

  地図の球の数は「同じ束を同じ向きに、時間の重なる球を 1 つにまとめる」（D33）ので、時間が変われば数も変わる。「畳んでも地図の球の数は変わらない」は成り立たないので、条件にしない
- **球を写す**: `flowOn(view, schedule)` → 見えている線の上の球（同じ線を同じ向きに、時間の重なる球は 1 つ。D33）と、単位の脈動（単位の中の線。最短 0.3 秒）。何も畳んでいなければ、線の球は今の `drawnBalls` と同じ
- **地図と共有するのは 2 つだけ**: 重なりをまとめる関数（今の `mergeOverlaps` を export する）と脈動の最短時間（`PULSE_MIN`）。**`litOnMap`・`mapFlow` の本体は触らない**（地図は戻りを行きの束に逆向きで乗せる・host と deploy の束を足す、と規則が違う。包みにしても Phase 9 で捨てる）。地図は今と同じく、配線図の `Player` の schedule を `mapFlow` で写す（2 面の球は同期したまま）
- **選択の種類を 1 つ足す**: `{ kind: 'container', id, slice?, members, label }`（今の `{ kind: 'group' }` は地図のノード用のまま変えない。流用すると、ディレクトリにメモが書ける・`?sel=` が別の選択で戻る、が起きる）
  - たどり方は group と同じ（`members` の箱ごとにたどって合わせる）
  - 畳んだ箱のクリックは `slice` 付きで、`members` は**その置き場の中の箱だけ**（割れた畳んだ箱は、クリックした 1 つだけが始点になる）。`▾` の横の名前のクリックは `slice` 無しで、入れ物の中の箱全部
  - メモの札は、`memo` のある入れ物を選んだときだけ（キーは `memo`）
  - `?sel=` の値: `<入れ物の id>` か `<入れ物の id>@<置き場のキー>`。解く順は 地図のノード → 箱 → 入れ物 → 入れ物 ＋ 置き場（最後の `@` で分ける）。どれも既知の id との照合だけで、解けなければ今と同じ警告
- 8-8 でやるのはここまで。**地図そのものを「同じ木の別の切り口」にする（`projectMap` の v2 → v1 の写し直しをやめる）のは Phase 9**

### 2.4 操作

| 操作 | 結果 |
|---|---|
| 畳んだ箱をクリック | 選択（その置き場の中の箱ごとにたどって合わせる） |
| `▸` をクリック / 畳んだ箱をダブルクリック | その入れ物を 1 段開く |
| `▾` の横の名前をクリック | その入れ物を選択（中の箱が全部光る） |
| `▾` をクリック | その入れ物を畳む |
| Enter | 開く（下の規則） |
| Shift + Enter | 畳む（下の規則） |
| 題名の横のボタン | `まとめて表示`（初めの切り口）／ `すべて開く`（平らな表示） |

- **クリックの判定**: 畳んだ箱は `data-fold`、`▸`・`▾`・名前は `data-crumb` の属性を持ち、今の順（型 → 項目 → 線 → 箱 → host → 空白）の**いちばん先**に見る（`data-box` を付けない。今の箱の「2 回目のクリックは下流だけ」が畳んだ箱に当たらない）。ダブルクリックは、その前に click が 2 回来る。2 回とも同じ選択になり、そのあと開く（「選択は 1 回のクリックと同じ」）
- 畳んだ箱の口へ集まる線のクリックは、中身が 1 本ならその線の選択（今と同じ）、2 本以上なら選択にしない（開けば 1 本ずつ選べる）。Esc・`F`・「選択中は hover が効かない」（D31）は変えない
- **Enter**: 選択が畳んだ箱（入れ物）なら、その入れ物を 1 段開く。選択の始点が 1 つの箱（箱・項目・線の選択）で、その箱が畳まれていれば、始点までの入れ物を全部開く（1 回で始点が見える）。始点が複数（group・host・型）なら、始点を含む見えている畳んだ箱を、それぞれ 1 段開く（押すたびに 1 段）
- **Shift + Enter**: 選択の始点を全部含む、いちばん内側の開いた入れ物を畳む（選択が入れ物なら、その親）。無ければ何もしない
- Enter・Shift + Enter が効かないとき: フォーカスがボタン・リンク・`select`・入力欄にある、キーの押しっぱなし（`repeat`）、IME の変換中（`isComposing`）。キーは最後に触った面へ（8-6 の規則）
- `▸`・`▾` はフォーカスできる（`tabindex="0"`・`role="button"`・`aria-expanded`・`aria-label`「<名前> を開く / 畳む」）。フォーカスがあるときの Enter・Space は、その入れ物の開閉
- **選択は切り口を動かさない**。畳まれている箱が選ばれたら（地図のクリック・`?sel=`・警告の一覧から）、見えているいちばん近い祖先の畳んだ箱に始点の輪を出し、そこへ視点を寄せる。中を見たいときは Enter
  - 例外は 1 つ: **`?view=` で開いたときだけ、読み込みのときに 1 回、始点までの入れ物を開く**（view は「この画面のこの項目から」を見せる入口。開かないと、画面（iframe）が 1 つも見えず、項目の流れが畳んだ箱の間の球になる）。view をあとから選んだときは開かない
- **開閉したあとの見え方**（枠と「順が変わらない」の代わり）
  - 操作した単位の左上を、画面の同じ位置に留める（開いたときは、中の単位のうち宣言の順で最初のもの。畳んだときは、できた畳んだ箱）
  - 新しく現れた単位の縁を 1 回だけ光らせる（`prefers-reduced-motion` では出さない）
  - 動きのアニメーションは付けない
- 平らな表示（§2.5）では `▸`・`▾`・Enter・Shift + Enter は無い（今の配線図そのもの）

### 2.5 最初の状態と URL

- 表示は 2 つ: **平らな表示**（今の配線図そのもの。畳む部品は何も出ない）と**畳んだ表示**（切り口を持つ）
- **箱（枠を除く）が 100 以下**: 既定は平らな表示。**fixture-poly（67 箱）の既定の見た目は変わらず、既存の e2e（8-6 の時点で 58 件）は 1 行も変えない**。100 はそのための境（合成の graph では、半分の幅の面に全体を入れる倍率が 100 箱で 0.1 を切る。§5.2 の G）。題名の横の `まとめて表示` で畳んだ表示にできる
- **100 を超える**: 既定は畳んだ表示。初めの切り口は

  ```
  open = {}（全部畳む）
  繰り返す: next = open ＋ 今見えている入れ物の全部（1 段）
    next が open と同じ → 終わり
    next で見える単位が 24 以下 → open = next で続ける
    24 を超える → open で見える単位が 4 未満なら open = next（上限を超えても 1 段だけ開く）。終わり
  ```

  実リポジトリは 18、合成 300 箱は 14 で始まる。下限 4 は、根の下が大きい段 1 つだけの graph が 1〜3 個の畳んだ箱で開くのを避けるため（§5.2 の H）
- **開いた直後の視点**: 畳んだ表示は**常に全体を入れる**（今の「倍率が 0.6 に届かなければ、0.6 で最初の画面の箱へ寄せる」は使わない。畳んだ箱の名前は 16px なので、倍率 0.375 で 6px。最初の画面の箱は畳まれていて配置に無い）。`?sel=`・`?view=` があれば、今と同じくそこへ寄せる
- 木に畳めるものが無い graph（`file` も `group` も無い）は平らな表示だけで、題名の横のボタンも出さない
- **URL**: `open` を**繰り返す**（`?open=<id>&open=<id>`。`URLSearchParams` の `getAll` で読む。`,` 区切りにしない: パスや group の値は `,` を含みうる）
  - `open` が無い = 上の既定。`?open=`（空の値 1 つ）= 全部畳む。**`?open=*` = 平らな表示**（切り口ではなく、別の表示）
  - 値は**既知の入れ物の id との照合にだけ**使う（DOM・セレクタ・HTML に入れない）。無い id・祖先が開いていない id は捨てる（正規の形に直す）
  - 書くときの正規の形: 既定と同じなら `open` を全部外す。id は木の宣言の順
  - 上限: 読むのは 256 個まで・1 つ 512 文字まで（超えた分は捨てる）。書く値の合計が 2,000 文字を超えたら `open` を書かない（その切り口は URL に残らない）
  - 開閉のたびに `replaceState` で更新する。`replaceState` は try / catch で囲む（回数の制限や `file:` で失敗しても表示は続ける）
  - 「全部の入れ物を 1 つずつ開いた切り口」と `?open=*` は、配置は同じで、`▾ <名前>` があるかどうかだけが違う。最後の 1 つを開いても平らな表示には切り替えない
- `?sel=`・`?view=` とは独立（`?view=` が `?sel=` に勝つのは今のまま）。`?view=` が始点まで開くのは、`open` を当てたあとに足す
- **localStorage には持たない**（URL が正。再読み込みは URL で戻る。build し直して id が変わったときに古い状態が残らない）。**views にも持たない**（graph.json の契約を変えない。Phase 9 で入れ物の id が決まってから）

### 2.6 配置: 開閉のたびに、今の配置をそのままやり直す

- **規則**: 配置 = `layoutWiring(foldView(…).index, { widthOf })`。配置は **(graph, 切り口) だけで決まる**。開く順に依らない・開いて閉じると元と同一・URL で開いたものと同一
- **配置の中核は変えない**（`packages/wiring/src/layout/` の変更 0。レーンのキーを返す関数の export を 1 つ足すだけ）
- **開閉で、開いていない箱の並びが変わることがある**（実測。開く前と後の両方にある箱の対で数えた。§5.3 の「平ら」）

  | | fixture-poly（29 通り） | 合成 300（26 通り） | 実リポジトリ（20 通り） |
  |---|---|---|---|
  | 左右が逆になった対（中央 / 最大） | 0 / 0 | 0 / 0 | 0 / 8 |
  | 同じ列で上下が逆になった対（中央 / 最大） | 4 / 8 | 128 / 250 | 7.5 / 92 |
  | それに関わる箱（中央。かっこは両方にある箱） | 4（14） | 48（56） | 8（17） |
  | 入れ替わりの無い場合 | 6 | 1 | 2 |
  | 配置の時間 | 約 2ms | 約 16ms | 6〜9ms（最大 21） |

  左右（呼び出しの深さ）はほぼ保たれ、同じ列の中の上下が入れ替わる。合成 300 は箱がどれも同じ形なので入れ替わりが多い。これを「操作した単位を同じ位置に留める」「現れた単位を 1 回光らせる」で補う（§2.4）
- **入れ子のレイアウトを作らない理由**（スパイク 1。§5.3）: 入れ物ごとに中を先に配置し、外からは大きさとピンの決まった 1 つの箱として扱い、外の順は子を全部畳んだ形で決めて凍らせる、という案を、配置のコードの写しに 17 か所の変更を入れて作り、測った
  - 順は変わらない（入れ替わり 0）。時間も足りる（開閉 1 回 最大 23ms、合成 300 の根を開く 36〜38ms）
  - **大きさ**: 同じ切り口を平らに配置したものに対して、fixture-poly で中央 1.41 倍・最大 2.39 倍、実リポジトリで中央 2.11 倍・最大 2.97 倍（基準は中央 1.3・最大 1.6）
  - **交差**: fixture-poly で中央 123（平らは 89）、実リポジトリで中央 979（平らは 340）
  - **開いた直後**: 実リポジトリの初めの切り口（18 単位）が 2004×1020・倍率 0.70 → 2196×2250・倍率 0.36。受け入れ条件（0.5 以上）を割る。全体を読めるようにする、という 8-8 の目的に逆らう
  - 順を凍らせずに段ごとに決め直すと、大きさは少し戻るが（実リポジトリで中央 1.47 倍）、順が変わるうえに基準も満たさない
  - 形のそろった合成 300 だけは全部の基準を満たす。実物に近い 2 つで落ちる
- **時間**（1440×900、手元の機械）: 開いた直後の配置 2〜11ms（今は実リポジトリで初回 432〜581ms）。開閉 1 回の配置は上の表のとおりで、いちばん重いのは合成 300 の根を 1 段開く場合（58 単位・線 438 本）の 16〜44ms。目標は、開いた直後の配置 50ms 以内、開閉 1 回は配置 50ms・描き終わるまで 100ms 以内

### 2.7 置き場所と計算の時期

- 木・切り口・写しは全部 `@stack-atlas/wiring`（純 TS・DOM 無し・決定的）。ビューアは `@stack-atlas/core` に依存しない（D44）
- **build 時に事前計算しない・覚えない**。木を作るのは 3ms 以下、切り口の graph を作って配置するのは 2〜44ms。開閉のたびにブラウザで計算する
- graph.json・スキーマ・CLI は変えない

### 2.8 ビューアの変更

- 状態を 1 つ足す: 表示（平ら / 畳んだ）と切り口。開閉 = 新しい `foldView` → 新しい配置 → **場面を当て直す**（8-7 の `setScene`）。選択は当て直すだけで、選択そのものは変えない
- 光らせる・球: 選択 → `select`（全体の索引）→ `litOn` → 塗りの計画。`Player` は `foldLengths` の時間で schedule を作り、`flowOn` の球と脈動を描く。平らな表示では今の経路のまま（`litOn`・`flowOn` を通さない）
- 畳んだ箱・`▾ <名前>` の描画、開閉の操作、`open` の読み書き、題名の横のボタン（`.wv-top a.alt-link` にはしない。既存の e2e がその 1 つを数えている）
- 画面の箱（iframe）: 畳まれた中にある間は隠す（壊さない。開いたときに読み込み直さない）
- 配線図には検索が無い。畳むと、箱を名前で探す手段は「地図の検索 → 地図のノードをクリック → 配線図の見えている祖先に輪」だけになる（配線図の検索は 8-8 では作らない。§8）

### 2.9 8-7 に求めるもの

8-7 の設計（docs/18 §11.3 の「折りたたみへの継ぎ目」）が約束しているものを、8-8b はそのまま使う。

| # | 8-7 が約束しているもの | 8-8b での使い方 |
|---|---|---|
| 1 | `setScene` は、違う配置・索引で何度でも呼べる | 開閉のたびに、畳んだ索引と配置で呼ぶ |
| 2 | 当てたあと、今の選択を当て直す | 選択は変えずに、`litOn` で写したものを塗る |
| 3 | `Player` は周回の中の同じ割合の位置から続ける（`rescaleTime`） | §2.3 の時刻の規則そのもの |
| 4 | 視点は動かさない（どこを映すかは呼ぶ側） | 操作した単位を同じ位置に留める（§2.4）のは 8-8b が決める |

足りないもの（8-7 の実装がこうなっていれば、8-8b は場面の中身を足すだけで済む。なっていなければ、8-8b の最初の変更になる）:

- **選ぶ索引と描く索引を分けられること**。8-7 は「選ぶ側の索引は 1 つのまま」としている。8-8b では、選ぶのは全体の索引、描くのは畳んだ索引になる。塗りの計画（`paintPlan(場面, 分岐, 光るもの)`）は、光るもの・今の分岐に無い線と項目を**描く索引の語彙の値**として受け取り、中で `select`・`wireActive` を呼ばない（呼ぶなら、差し替えられる引数にする）
- **`Player` の 2 つの入力を差し替えられること**: 線の時間（`schedule` の `lengthOf`）と、描く球の出し方（今は `drawnBalls` と `segmentRoute(配置, 区間)`）。場面から読む形にする
- **クリック・hover は根で受ける**（要素ごとにリスナーを付けない）。`setScene` のあとも効き、判定の先頭に `data-fold`・`data-crumb` を足せる
- **要素の Map を場面の外から引けること**（単位の id → 要素）。現れた単位を 1 回光らせるのに使う（点滅の `flash.ts` を箱の縁にも使えるとよい）
- **画面の層は、配置に無い画面の箱を隠すだけで壊さない**（`setScene` で iframe を作り直さない）

8-8a（wiring だけ）は 8-7 に何も求めない。

### 2.10 3D の地図との関係

- **地図は 8-8 で変えない**（`projectMap` の単位 = group × runtime のまま）。選択の正は配線図（D111）、球の時刻の正は配線図の `Player`（D106）。配線図を畳むと `Player` の schedule が変わるので、地図の球の時刻・周期も一緒に変わる（2 面は同期したまま。光る集合と、球の載る束は変わらない。§2.3）
- 地図のノードをクリック → 配線図は、その group を含む見えている単位（畳んだ箱か、開いていれば中の箱）が光る。配線図の開閉は地図の選択を変えない
- 配線図の畳んだ箱をクリック → 地図は、中の箱の単位が光る（今の `litOnMap` のまま）。group の入れ物と地図のノードは 1 対 1 ではない（地図は 1 箱の group も単位にして runtime で割り、配線図は 2 箱以上で置き場で割る）。対応は箱を通して取るので、id を合わせる必要は無い

## 3. 受け入れ条件とテスト

**数（1440×900。実リポジトリは手元で測り、数だけ記録する）**

| | 条件 |
|---|---|
| 開いた直後に見える単位 | 実リポジトリ ≤ 24（設計の実測 18）、合成 300 箱 ≤ 24（同 14） |
| 全体を入れたときの倍率 | 1 面で ≥ 0.5（畳んだ箱の名前 16px が 8px 以上。実測 0.70・0.68）。2 面の半分の幅で ≥ 0.3（実測 0.34・0.33） |
| 開いた直後の配置 | ≤ 50ms（合成 300 箱・実リポジトリ） |
| 開閉 1 回 | 配置 ≤ 50ms、描き終わるまで ≤ 100ms |
| 配置の決まり方 | (graph, 切り口) だけで決まる（開く順に依らない・開いて閉じると元と同一・URL で開いたものと同一） |
| 開閉で保たれるもの | 選択（光る集合）、再生バーの割合、地図で球の載る束と向き（§2.3 の表） |
| fixture-poly の既定 | 今と同じ（既存の単体テスト・e2e を変えない） |

**時間の条件の確かめ方**: 配置の時間は CPU 時間の単体テスト（wiring。今の `layout-perf.test.ts` の形。合成 300 箱は wiring の `__tests__/synthetic.ts` にあり、ビューアの e2e からは読めない）。描き終わるまでの時間は CI に入れず、測るスクリプトと結果を docs に残す（8-7 の時間の条件と同じ扱い。docs/18 §11.11 の D120）。

**単体テスト（wiring。8-8a）**

- 木: 基準の graph（poly-86）で入れ物 22（ディレクトリ 16・group 6）・根の子 3、決定的。全部畳むと見える単位 9、上限 24 の切り口で 16。合成 300 箱で 14
- 初めの切り口: 上限 24 で止まる。下限（見える単位が 4 未満なら、上限を超えても 1 段だけ開く。根の下が 1 つだけの graph で 1 → 25）
- 切り口: 正規の形（祖先が開いていない id を捨てる・畳むと下を忘れる）、開いて閉じると元の切り口と同じ
- 写し: 全部の線が「見えている線 1 本」か「単位の中」のどちらか 1 つに入る（合計が線の数と合う）。全部開いた切り口で、畳んだ graph の箱・線の順が元と同じ・配置が平らな配置と同じ。何も畳まない写しで `litOn` が元の光るものと同じ、`flowOn` の線の球が今の `drawnBalls` と同じ
- 束: 単位は（from の端, to の端, 戻りか）。`via` は向きを決める線の最初のもの。分岐で全部止まった束は止まった線
- 切り口を変えても `select` の結果が同じ
- 時刻: 隠れた線は 0.25 秒・球が消えない。`route:/` で、13 通りの切り口のどれでも地図の球が 21（8-6 の数のまま）。67 通りの選択 × 13 通りの切り口で、地図で球の載る束と向き・脈動の数が同じ。再生位置の割合が開閉で保たれる（400 回開閉してずれ 0）。「地図の球の数が違う場合がある」は事実として固定する（871 通り中 88。数え直して変わったら、テストのコメントに何が変わったかを書く）
- 配置: (graph, 切り口) で決定的（開く順を変えても同じ・開いて閉じると元と同一）、箱が重ならない、見えている箱の項目の順が平らな配置と同じ（**実装で成り立たないと分かった。組は同じで順は変わる。§11.2**）、全部の入れ物を 1 つずつ開閉して落ちない
- 切れている線: 見えている線に `broken` が移る（path ごとに 1 つ・重い方）。両端が同じ単位に入った切れた線は、単位ごとの件数といちばん重い level で返る
- 差分: 幽霊を足した graph から作った木で、幽霊だけの入れ物・追加だけの入れ物・混ざった入れ物
- 敵対的な入力: 64,000 段のパスの `file`（時間が段の数に比例）、32 段を超える深さ、親の循環・無い親・`__proto__` という id の `Containment`、`d:` で始まる group の値、`fold:0:0` という id の箱、120 文字を超える名前
- 見つかったことの固定: host が混ざる入れ物が host ごとに割れる、割った結果が 1 箱でも畳んだ箱、1 箱だけの group は入れ物にならない、`file` の無い箱は根の直下、木に畳めるものが無い graph は元と同じ出力
- 回帰: `litOnMap`・`mapFlow` の今のテストは変えずに通る（本体を触っていないこと）

**単体テスト（ビューア。8-8b）**

- `open` の読み書き: 往復（`,` や `&` を含む id）、`?open=`（空）と無しと `*` の区別、既定と同じなら外す、無い id・祖先が開いていない id を捨てる、256 個・512 文字・2,000 文字の上限
- 既定の表示: 100 箱は平ら・101 箱は畳む。`?prev=` の幽霊は数えない
- `?sel=`: 入れ物・入れ物 ＋ 置き場の読み書き、箱と入れ物の id が重なったときに箱が勝つ

**e2e（fixture-poly を `?open=` で開く。既定は畳まないので）**

- `?open=`（空）: 見える単位 9（畳んだ箱 8・箱 1）。畳んだ箱をクリック → 輪と球（束の上）。`▸` → 中の単位が `▾ <名前>` 付きで出て URL が変わる。`▾` → 元の配置に戻る。Esc で選択だけ解ける
- 畳んだ箱をダブルクリック → 開く（選択は 1 回のクリックと同じ）
- `?sel=<畳まれた中の箱>&open=`: 祖先の畳んだ箱に輪。Enter → 始点まで開く。Shift + Enter → 畳む

- `?open=*` と既定（パラメータ無し）が同じ見た目。題名の横の `まとめて表示` → 見える単位 16

## 7. Phase 9（モデルを 1 つに）との関係

Phase 9（docs/22 で設計）: graph が包含の木（repo > ディレクトリ > ファイル > 関数の箱 > 口 > 項目）を持ち、3D の地図と配線図は同じ graph の 2 つの切り口になる。`projectMap` の v2 → v1 の写し直しと graph.v1.json は無くなる。

**そのまま使うもの**

- `Containment` の形（`kind` は開いた文字列、`memo`）と、切り口（開いている入れ物の集合・正規の形）
- `foldView`（切り口 → 見えている単位・線・キーの対応。置き場は引数）、`litOn`・`flowOn`・`foldLengths`
- ビューアの開閉の操作・`open`・場面を当て直す流れ・選択の種類 `container`

**Phase 9 で置き換えるもの**

- `containmentOf(graph)`（今の項目から木を作る関数）→ graph の木を読むだけになる。**8-8 の中で捨てるのが決まっているのはここだけ**（小さい: 関数 1 つとそのテスト）。これが無いと 8-8 は実リポジトリで効かないので、先送りせずに作る
- `projectMap` の単位の規則・id の規則（`group:`・`@runtime`）→ 「group の段の切り口」での `foldView` になる。`litOnMap`・`mapFlow` はそのとき要らなくなる（8-8 では触っていないので、8-8 のせいで捨てる量は増えない）。選択の種類 `group`（地図のノード）と `container` も 1 つになる
- 入れ物の id（`d:<パス>`・`g:<group の値>`）→ 木のノードの id。8-8 の `open` の URL は Phase 9 で開けなくなるかもしれない（無い id は捨てるので、既定の切り口で開く）
- 置き場の既定（`slicesOf`: host、無ければレーン）は、木が runtime・host を持てば変わる。`foldView` は引数で受けるので変えない

**木がもう在ったら変えていた所**

- 木を作る関数は書かない。ディレクトリの入れ物にもメモを書ける（id がある）。切り口を views に保存できる
- 「group ≒ ファイル」の読み替えが要らない（ファイルの段がある）
- 置き場で割る規則は、木が runtime・host を持たない限り Phase 9 でも要る
- 箱そのものも入れ物（口 > 項目）になるので、「箱を口 1 行に畳む」も同じ切り口で書ける。8-8 では作らない（項目だけ閉じても倍率 0.08 で効かない。§5.2 の B）

**先送りするもの**（作っても Phase 9 でやり直しになる）

- 切り口を views・graph.json に入れること、ディレクトリの入れ物のメモ、地図を切り口から描くこと。どれも 8-8 では作らない
- 枠と入れ子のレイアウト。今の配置（8-3a）の上に載せる形では基準を満たさなかった（§5.3）。やるなら、外と中を一緒に最適化する配置に作り直す話で、木が graph に入ったあとに考える

## 9. 危ない所

- **開閉で、同じ列の中の上下が入れ替わる**（§2.6 の表。実リポジトリで中央 8 箱、合成 300 では両方にある 56 箱のうち 48 箱）。補い（同じ位置に留める・1 回光らせる・`▾ <名前>`）で足りるかは、8-8b を実リポジトリで見ないと分からない。足りないときに試す案（未検証）: 列の中の並びの出発点を、切り口に依らない順（全体の graph での宣言の順）から取り、開いても相対の順が残りやすくする。配置は (graph, 切り口) だけで決まるまま
- **枠が無い**。同じ入れ物の単位は、置き場と層で決まる場所に置かれるので、隣り合うとは限らない。まとまりは `▾ <名前>` と、名前のクリック（中が全部光る）でしか見えない
- **畳むと球の 1 周が短くなり、地図の球の数が変わることがある**（871 通り中 88。§5.4）。2 面で見ていると、配線図を開閉したときに地図の球の出方が少し変わる。光る集合・球の載る束・再生バーの割合は変わらない
- **畳んだ graph の層は、全体の graph の層と同じとは限らない**。今の配置は「項目を持つ箱の `out/_` から出る線」を参照の線として層の計算から外すが、畳んだ箱は `_` しか持たないので、そこから出る線は向きを決める線として働く。見え方（どの単位が左か）だけの話で、たどる規則は全体の graph のままなので、光るものは変わらない
- 置き場で割るので、同じ名前の畳んだ箱が host・レーンごとに並ぶ（実リポジトリで 1 つの入れ物から最大 5 個、合成 300 箱は 14 個とも同じ名前）。場所で見分ける設計だが、実物を見て分かりにくければ、名前の付け方を変える
- 目標の時間に余裕が無い所がある: 合成 300 箱で根を 1 段開く（58 単位・線 438）と、配置だけで 16〜44ms（目標は 50ms）
- 木の段が粗い（次の段を開くと 18 → 53）。上限 24 と 53 の間が無いので、開いた直後の細かさは graph のディレクトリの切り方に左右される
- 半分の幅の面では、畳んでも全体表示の名前は 5〜7px。2 面で全体を読むには、境目を動かすか 1 面（`?pane=wiring`）にする
- 口へ集まる線（中身が 2 本以上）はクリックしても選べない。開けば選べるが、「この束には何が通っているか」を畳んだまま知る手段は `<title>` の件数だけ
- **8-7 はまだマージされていない**。§2.9 の「足りないもの」（選ぶ索引と描く索引を分ける・`Player` の 2 つの入力・根で受けるクリック）が実装に入っていなければ、8-8b の最初の変更になる
- 決定の番号: 8-7 が D114〜D122 を使っているので、8-8 は D123〜D134。8-7 が実装の途中で番号を足したら重なるので、マージの前に確かめる

### 11.2 設計と違う形になった所

1. **見えている箱の項目の順は、平らな配置と同じにならない**（§3 の「配置」の項目）。項目の行の順は配置（8-3a）が交差を減らすように決めるので、まわりの単位が変われば変わる。項目の組は同じ。（見えている箱 × 切り口のうち順が変わったもの）poly-86 で 25 / 102、合成 300 で 260 / 300。テストは事実として固定した。8-8b では、開閉で同じ箱の項目の行が入れ替わることがある（§2.6 の「上下の入れ替わり」に足される）
2. `foldLengths(view, layout, { speed, hidden })`: 引数を `hidden` だけでなく `speed` も取る形にした（`schedule` が長さを速さで割るので、隠れた線を「hidden 秒」にするのに要る）。既定は `FOLD_HIDDEN` = 0.25 秒
3. `FoldView` に `source`（全体の索引）と `folded`（畳んだ箱があるか。false なら `graph`・`index` は元のものそのもの）を足した。`unitOf` は host の枠も持つ（自分自身へ）
4. §8 の表に無い export: `segmentOn`（区間を畳んだ索引へ写す。`litOn`・`foldLengths`・`flowOn` が使う）、`lineActive`（束は中の線が 1 本でも存在すれば存在する。束に `when` は付けない）、`foldWidthOf`・`FOLD_WIDTH`（200）・`FOLD_HIDDEN`、`hostSlice`・`laneSlice`（置き場のキー `h:<host>`・`l:<レーン>`）、`DIR_MAX_SEGMENTS`（32）
5. 畳んだ箱のノードの `kind` は `fn`（スキーマの kind は閉じた集合。ビューアは `view.units` で畳んだ箱かを見分ける）。口は `in/_`・`out/_`（項目の名前「値」、型 `unknown`）
6. `hiddenBroken.count` は線の本数ではなく `broken` の件数
7. `group` が文字列でない箱は group 無しとして扱う
8. 分かっている端（§9 に足す）: 畳んだ箱の runtime と host は中の最初の箱のもの。レーンをまたぐ host の箱を一部だけ畳むと、畳んだ箱が平らな配置と別のレーンに出ることがある。畳んだ箱から出る束は、層を決めるとき向きを決める線として扱われる
