# 01. ビジョンと要件

## 結論

大きめの開発を主導する人が、**インフラからコードの型まで 1 画面で俯瞰でき、関係とデータの流れを指でたどれる共有スペース**をつくる。
「データの流れも型もパーツ構成もこれで分かる。メモも書き込める」状態がゴール。

## ユーザーの元の要望（要約・原文に近い形）

> Figma に 3D 機能を持たせたい。スタックからコードまで全部 1 画面で追いたい。
> 比較的大きめな開発を主導して環境構築から行う。ぶっちゃけ追いきれないので、1 画面に全部載せて見れるようにしたい。コードも同じ。
> 例えば Lambda に Next を載せてビルドするなら、Lambda の下（Z 軸）には Next があって、そこからさらに展開して全ての画面が展開されている。
> コンポーネントや型定義が整理されており、コンポーネントや画面など構成単位に 1 つカーソルを合わせると、型定義や共通して使われている他の画面のパーツなどが赤くハイライトされる。
> データの流れも型もパーツ構成もこれで分かる！メモも書き込める！みたいな共有スペースが欲しい。
> 連結はリポジトリからコードを引っ張ってくればいけると思う。インフラ・バックエンド・フロントエンド、全部コード管理しているので。

その後の追加要望:

> データフローが見えるのが最高。キャッシュも表現できたら実務で使える。
> フロントの画面は箱ではなく実際の画面（スクショ）で貼りたい。
> 層ごとにつながる線は上の階層の色にしてほしい（どこからどこにつながっているか分かりにくいのを解消）。
> どんなプロジェクトにも適用できるようにしたい。

## 要件

### 必須（MUST）

| ID | 要件 |
|---|---|
| R1 | インフラ・画面・コンポーネント・型を**層として Z 方向に積み重ねて** 1 画面に表示する |
| R2 | 「インフラリソースの下に、その上で動くアプリが展開される」包含関係が見える（例: Lambda → Next.js の各ルート） |
| R3 | 任意のノードにホバーまたはタップすると、**依存先と影響範囲がハイライト**される（型定義、共通パーツ、それを使う他の画面） |
| R4 | 画面ノードは**実際の画面（スクショ）**で表示し、画面内のコンポーネント領域も同じルールでハイライトされる |
| R5 | **データフロー**（リクエストが層をまたいで流れる経路）をアニメーションで表示できる |
| R6 | **キャッシュ**（どこに、どれだけの期間、どう無効化されるか、HIT／MISS 時の経路の違い）が見える |
| R7 | ノードに**メモ**を書ける。最終的にはチームで共有する |
| R8 | 関係データは**リポジトリの解析で自動生成**する（手書きを前提にしない） |
| R9 | **どんなプロジェクトにも適用できる**（スタック固有の処理を差し替え可能にする） |
| R10 | 層をまたぐ線は**上の層の色**で描く |

### 望ましい（SHOULD）

- 層の表示／非表示の切り替え、重ねる／展開の切り替え（Figma 的な平面の重なりと 3D 展開の行き来）
- ノードを選ぶとコード抜粋、ファイルパス、依存一覧、キャッシュ設定が見えるパネル
- スマホ（iPhone）でも閲覧・タップ操作ができる
- CI で毎回再生成し、常に最新の状態を保つ

### 非機能

- 業務コードを扱うため、**解析結果やソースを外部 SaaS に送らない**。ローカルまたは自前ホスティングで完結
- 数百〜千ノード規模でも操作できる（層の折りたたみ、フィルタ、詳細度の切り替えが必要になる見込み）
