# 18. 設計: 配線図のビューア（Phase 8-3）

作成: 2026-11-09。`docs/15` §3.5〜§3.9（たどる・表示・折りたたみ・名前付きの始点）と `docs/14` §3.3（ビルド成果物の画面）を、8-0 の配線図（`packages/viewer/src/wiring/`・`packages/wiring/src/layout.ts`）の上に実装する設計。8-2 で graph が項目の単位になり、箱が 50（fixture-poly）〜数百（実リポジトリ）に増えた。今のレイアウトでは fixture-poly の 8-2a の出力が 3348×6486 の縦長になり、全体表示で文字が読めない。設計レビュー（§7）を反映した版。

## 1. 結論

- **レイアウトを作り直す（ELK は入れない）**。レーンは今のまま左から右。箱の多いレーンだけを、呼び出しの深さの境目で列に割り、図全体を 16:10 に近づける。列を 2 つ以上またぐ線には高さ 0 の通過点を置いて、列の中の順と縦の位置を決める計算に参加させる（Sugiyama 法のダミー）。host の枠（Lambda など）は中を先に配置して 1 つの塊として扱う。**配置は graph ごとに 1 回だけ決め、選択や分岐の切り替えでは箱を動かさない**
- **group の自動の折りたたみはしない**（docs/15 §3.8 の全体表示の折りたたみは保留。Q19）。ユーザーの要望「I/O は常に全部開いておく」「畳んだ箱と束の線は分かりにくい」を優先する。代わりに、開いた直後は**読める倍率**（項目の文字が 6px 以上）で画面の箱のあたりを映し、全体は縮小して見る。実リポジトリ（8-5）の画面を見てもらってから、畳むかどうかを決めてもらう
- **画面の箱の中にビルド成果物の HTML を出す**（docs/14 §3.3）。新しい抽出器 `screens` が HTML を写して許可リストで消毒し、ビューアは `allow-scripts` 無しの sandbox の iframe を SVG の下の層に縮小して置く。`serve` は画面の HTML に CSP の応答ヘッダ（`sandbox` 付き）を付ける。依存は足さない
- **views・memos・diff を v2 に**。diff は `@stack-atlas/wiring` に移す（ビューアは core に依存しない。D44）。検証の警告は題名の横の文字のリンクにする

## 2. 全体像

```
graph.json（v2）
   │
   ▼
@stack-atlas/wiring
   ├─ layout（§3.1）: レーン → host の塊 → レーンを列に割る → 通過点 → 列の中の順 → 縦の位置 → 直交配線
   │                   （graph ごとに 1 回。選択・分岐の状態は入力に取らない）
   └─ diff（§3.4）: core から移す（core は再 export）
   │
   ▼
viewer/wiring
   ├─ 画面の層（§3.3。iframe。SVG の下）＋ SVG（箱・線・球・画面の領域の枠）
   ├─ 操作: クリック・hover・Esc（今のまま）、views の選択
   └─ メモ・差分・警告のリンク
```

## 3. 構造

### 3.1 レイアウト（`packages/wiring/src/layout.ts`）

8-0 の規則（重心で並べる、線の数で隙間を決める、直交配線、線は箱を通らない、項目は相手の並びに合わせて並べ替える）は残し、次の手順に置き換える。8-0 の縦長の原因は、重心で置く位置が下へ連鎖することと、1 レーン = 1 列で箱が縦に積まれること（docs/16 §10 の記録）の両方。

1. **レーン**: `runtime` → レーン（今のまま。箱の無いレーンは出さない）
2. **host の塊**: 同じ `host` の箱の集まり（Lambda・ECS・Aurora の枠）は、まず中だけで手順 3〜7 を行って大きさを決め、外側の配置では 1 つの箱（塊）として扱う。外の線は塊の縁を通って中の項目のピンに着く（枠は背景で、箱ではないので線が横切ってよい）。塊の中の箱は中の配置のまま動かない。外の箱が塊に重なることは無い
3. **層（呼び出しの深さ）**: 同じレーン（塊の中なら塊の中）の箱どうしの線のうち、**呼び出し・props・render・http の向きの線**（`reply` と、呼び出しでない参照の `_` の線を除く）で有向グラフを作る。閉路は DFS の後退辺を外して切る。最長経路で層を付ける。**入ってくる線の無い箱は、後続の層の最小値のすぐ左**に置く（列 0 に集めない。`fn:getEntries` が画面と同じ層に並ばない）
4. **レーンを列に割る**: 最初は 1 レーン = 1 列。全体の幅と高さから縦横比を出し、16:10 より縦長なら、**いちばん高いレーンを層の境目で 1 つ割る**（層の高さの累積がほぼ半分になる所）。16:10 に近づかなくなるか、割れる境目が無くなるまで繰り返す。割った列には層の順に箱を入れる。レーンの背景はそのレーンの列を全部含む
5. **通過点**: 2 つ以上の列をまたぐ線（レーンをまたぐ線も含む）には、間の列ごとに高さ 0 の通過点を置く。通過点は列の中の順と縦の位置の計算に参加し、線はその y を通る。`reply` の線は、対になる呼び出しの線の通過点の隣を逆向きに通る（呼び出しと戻りが並んで走る）
6. **列の中の順**: 初めの順は宣言の順（items の `row`、なければ graph の nodes の順。docs/15 §8 #13・#16）。仮の y は初めの順に積んだ位置。左右交互に 8 往復、**項目のピンの y の重心**で並べ直す。同じ `group`（無ければ file のディレクトリ）の箱は列の中で隣り合わせる。同点は初めの順で崩す（決定的）
7. **縦の位置**: 左から右へ、箱（と通過点）ごとに「左側でつながっている項目のピンの y の中央値」を目標にし、順序を保ったまま重なりを最小の移動で解く（PAVA）。左側に相手が無い箱は今の y を目標にする。右から左へも同じことをして、2 つの解の平均を取る（制約が線形なので平均も重ならない）。隙間の大きさ（そこを通る線の数 × 8px ＋ 余白）で y が変わるので、手順 6〜7 を 3 回繰り返す
8. **列の幅**: 列の中でいちばん幅の広い箱（画面の箱は通常の 2 倍）。通り道の幅はそこを通る縦の区間の数 × 8px ＋ 余白で、区間はトラックに左詰めで割り当てる（重ならない）
9. **配線**: 直交の折れ線。通過点の y を順に通る。後ろの列へ戻る線（同じ列の上下や、通過点の無い短い戻り）は今の「隙間を通る回り道」

**配置は graph ごとに 1 回だけ**決める。選択・分岐の切り替え・下流だけの絞り込みでは箱を動かさない（docs/15 §3.6「選択は沈めるだけで形は変えない」、docs/05）。build 時に配置を graph.json に埋める（docs/16 §10、D44 の後半）のは今回もしない。

性能の目安: 箱 300・項目 3000・線 1000 で、配置 1 回が CPU 時間で 300ms 以内。クリックから光るまで 50ms 以内（配置をし直さないので、たどる計算だけ）。

うまくいかないとき（受け入れ条件 §4 を満たせないとき）は、**build 時に ELK で配置を計算して graph.json に埋める**案をユーザーに出す（依存の追加は確認が要る）。

- docs/15 の古い記述（§3.5 の最後の行「全体表示は箱と束の線だけで、項目は出さない」、§3.8 の 3 つ目「関係する項目だけ開く」）は、この節と docs/15 §3.6 で置き換える

### 3.3 画面（ビルド成果物の HTML）

#### 契約

- v1・v2 の `screen` に `html`（graph.json からの相対パス）と `source`（`next-export` / `dir`）を足す（docs/14 §3.3 の契約）。v1 の `graph.schema.json`・`types.ts`・`docs/03` も直す（v1 の `screen` は `additionalProperties: false`）。`upgradeGraph` は `screen` をそのまま写す
- graph.json に `screen.regions` があればビューアの計測より優先する（今の規則。空の配列は無いのと同じ。§9.2 の 4）

#### 集める側: 抽出器 `screens`（`extractors/screens`）

- 設定 `screens: { repo, from: next-export | dir, dir, routes, viewport }`。`next-export` は nextjs-app が読む `next.config` の `output`・`distDir`（既定 `out`）に加え、**`trailingSlash`・`basePath`・`assetPrefix`** を読む（`basePath` があると `/_next` の写しが外れるため）。`dir` は任意のディレクトリ
- `route:` ごとに HTML を決める（`/` → `index.html`、`/a` → `a.html` か `a/index.html`（trailingSlash）、動的ルートは `routes` のサンプル）。無ければ何もしない（今のプレースホルダ）
- **消毒**（許可リスト。自前の字句解析。D63）:
  - 字句から**書き直す**（元の文字列を写さない）。doctype は先頭に残し、CSP の meta を **`<head>` の最初の子**に入れる（`<head>` を決められない文書は出さない）: `default-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; base-uri 'none'; form-action 'none'`
  - タグごとの属性の許可リスト。URL を持つ属性（`src` `href` `srcset` `poster` `background` `xlink:href` `ping` `formaction` `action` `data` `cite`）は全部、文字参照を解き空白・制御文字を除いてから scheme を見る。残すのは相対パスと、画像・フォントの `data:` だけ
  - まるごと落とす: `script` `noscript` `iframe` `object` `embed` `base` `meta[http-equiv]` `svg` `math` `template` `title` `textarea` `xmp` `noembed` `noframes` `plaintext`、コメント・CDATA、`on*` 属性、`<link>` の `rel=stylesheet` 以外。解析できない所（閉じていないタグ・未知の構文）は要素ごと落とす
  - `form` は `div` に書き換える（2026-11-09 変更（8-3b）。中身ごと落とすと部品のルート要素の `data-component` が消え、領域が取れない。属性は div の許可リストで、送信に関わる属性は落ちる。CSP の `form-action 'none'` と `allow-forms` 無しはそのまま）
  - CSS（`<style>` の中身・`style` 属性・写す CSS ファイル）は CSS の字句解析を通す。`@import`・`image-set()`・外部の `url()` を落とし、エスケープ（`u\72l(`）は解いてから判定する
- **資産の写し**: 同じ出所の CSS・フォント・画像（`/_next/static/...`、`public/`）だけ。読む元は realpath にして export のディレクトリと public の中に限り、シンボリックリンクは辿らない。拡張子は許可リスト（css woff woff2 ttf otf png jpg jpeg gif webp avif svg ico）。写した名前は内容のハッシュ（`_assets/<hash>.<ext>`）。**svg はファイルにせず**、画像として読む所（img の src・srcset、CSS の url() など）に `data:image/svg+xml;base64` で埋め込む（上限 256 KB。2026-11-09 変更（8-3b）。ファイルの SVG は応答ヘッダの無い配信で直接開くと script がビューアの origin で動きうる）。埋め込むのは 1 つの画面の HTML・CSS ファイルで合計 2 MB まで、消毒した HTML・CSS は 10 MB まで（§9.6）。外部 URL と落とした要素の数を `issues.json` に出す
- **regions のカバー率**（docs/14 §3.3 の 4）: route ごとに「HTML の `data-component` で解けた部品の数 ÷ その画面から呼び出しでたどれる部品の数」を `issues.json` に出す。0 なら警告（`data-component` を付けるきっかけ。ビルドは止めない）
- 出力: `out/screens/<slug>/index.html`、箱の `screen = { html, width, height, source }`。書く先は出力先の中だけで、シンボリックリンクを確かめる（build の既存の検査）。build は出力先の中の一時ディレクトリに書かせ、成功したら前回の `screens/`（印のあるもの）と入れ替える。印の無い `screens/` には書かない（§9.6）
- `screenshots` 抽出器はそのまま。両方あれば `screen.html` を優先して描く
- **後回し**（8-4 のハーネスで）: fixtures モードのビルド（対象アプリの変更が要り、エージェントが提案する）、`.stack-atlas/screens/*.html`（wireframe）と `regions.yaml`、外部 URL を `validate --strict` でエラーにすること（`--strict` は 8-4）

#### serve

- `/screens/**` の応答に `Content-Security-Policy: sandbox allow-same-origin; default-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; base-uri 'none'; form-action 'none'` を付ける。HTML をタブで直接開いても sandbox が効く。S3 / CloudFront で配るときに同じ応答ヘッダを付ける方法を docs/11 に書く

#### 描く側: ビューア

- 画面の箱（kind `screen`）に `screen.html` があれば、箱の中に縮小した実 DOM を出す。**iframe の層は SVG の下**に置き（SVG の背景は透明にし、画面の箱の中だけ抜く）、層全体を `pointer-events: none`。canvas と同じ移動・拡大の変換を掛ける。iframe は `sandbox="allow-same-origin"`（`allow-scripts`・`allow-forms`・`allow-popups` は付けない）、`referrerpolicy="no-referrer"`
- 画面の箱の大きさ: 幅は通常の 2 倍、高さは「viewport の比率の高さ」と「項目の行の高さ」の大きい方。HTML はビューポートの高さで切る（縦に長いページは上だけ）。項目のピンは箱の縁（2026-11-09 決定（8-3b）: 画面の領域を取るのは `screen.html` のある箱だけで、名前の帯の下に置く。§9.2）
- 読み込み: 画面上の幅が 200px 以上の箱だけ読む（`loading="lazy"` は変換の下で距離が決まらないので使わない）。同時に生かす iframe は 6 枚まで、画面から外れたら外す
- **部品の領域**: `load` 後、`fonts.ready` と画像を待って（上限 3 秒）`[data-component]` を測り、`comp:<名前>` → `hook:<名前>` → 末尾一致の順で箱 id に解く（screenshots 抽出器と同じ規則）。選んだ経路に入る部品の領域だけ、**SVG の側に**枠を描く（ラベルは出さない）
- 沈んだ画面は iframe の不透明度も他の箱と同じに下げる
- `contentDocument` が読めないとき（別 origin・ファイルを落として開いたとき）は、プレースホルダと graph の regions で描く

### 3.4 views・memos・diff・警告

- **views**: 題名の横に views の名前のメニュー（`select`）。選ぶと分岐の状態を既定に戻してから `variants` を当て、`start`（箱・項目・線のどれでも）から選択を始める。ほかをクリックしたらメニューは空の選択に戻る。`?view=<id>` で開ける（共有用）。views が無ければ出さない
- **memos**: `memos.json`（キーは箱 id。v1 と同じ）を読む。メモのある箱は**右下の角を折った形**で描く（右上は分岐の表、左上の外は種類の位置）。箱を選んだとき、左下に固定の札（不透明の背景、光る層の上）で本文を出し、その場で編集できる（3D の地図と同じ保存の仕組み: localStorage と、`serve --repo` なら `POST /api/memos`）。型をクリックしたときは型の id のメモ、箱のメモに加えて group（v1 の箱の id。D56）のメモがあれば同じ札に並べる。孤立したメモの判定は箱・型・group の id を見る
- **diff**: `?prev=<前の graph.json>`。前が v2 なら、`diffGraphsV2` で比べ、**今の graph に前にしか無い箱と線を足した graph** を配置して、足した分を灰の点線（幽霊）で描く。今だけにある箱・項目・線は緑の縁、`type` / `wireType` が変わった項目も緑の縁。消えた項目は箱の中に灰の点線の行で残す。前が v1 なら差分は出さず、題名の横に「前の graph が v1 です」（ビューアは v1 → v2 を変換できない）。`diffGraphsV2` は `@stack-atlas/wiring` に移し、core は wiring から再 export する
- **警告**: 検証の警告は図の上の枠をやめ、題名の横に文字のリンク（`警告 2 件`。3D の地図へのリンクと同じ並び）で出し、クリックで一覧を開く

| 開いた直後 | 1440×900 で、項目の文字が 6px 以上 |
| 性能 | 合成 300 箱で配置 1 回が CPU 時間 300ms 以内 |
| 画面 | fixture の画面の箱に iframe が出て、`[data-component]` の領域（id と座標 ±4px）が測れる。標準モード（`compatMode === 'CSS1Compat'`）。CSP の meta が全部の link / style より前。自分以外の origin への通信 0、script の実行 0（e2e）。消毒の単体テスト（§3.3 の落とすもの全部、文字参照の `javascript:`、CSS のエスケープ、壊れた HTML）。資産の写しのパストラバーサル・シンボリックリンクのテスト。`serve` の CSP ヘッダ |
| views・memos・diff | views の選択で始点と分岐が再現される（`?view=` も）。メモの印と札と編集の保存。v2 の差分で幽霊・緑の縁、v1 の前では文言だけ（e2e） |

1. **初めの順も塊を割らない**: 初めの順を y の順だけで並べていたので、線の無い列（往復が良くならず初めの順が残る）で host の中の箱の間に外の箱が入り、枠が外の箱に重なった。初めの順も並べ直しと同じ `sortWithGroups`（host・group の塊を隣り合わせる）にした。塊を守ると `/today` の交差が 45 → 56 になったので、**最後の回に入れ替え（`Placer.refine`）**を足した: 隣り合う単位（host・group）・単位の中の group・group の中の箱・自由な束と隣の塊を入れ替え、並べ方の悪さが減るものを残す。交差の増減は入れ替えた塊の線の組だけで数え、同じ列の中の線の長さは変えた所だけ積み直して数える。塊の数 ×（塊の数 ＋ 同じ列の中の線）が 100 万を超える列は省く。毎回でなく最後の回だけなのは速さのため（毎回だと基準の graph 411・合成の冷えた 1 回目 250〜300ms）

3. **並べ方の悪さの物差し**: 2 回目からの回の基準は PAVA の位置で、往復の後は積んだ位置で測っていた（同じ列の中の線の長さが食い違う）。悪さは並びだけで決まる値にし、いつも列を上から積んだ位置（`sy`）で測る。基準の graph・`/today`・合成の graph では数は変わらない

### 9.2 §3.3 から決めた・変えた所

1. **画面の領域を取るのは `screen.html` のある画面の箱だけ**（kind `screen` で html が空でない文字列）。html の無い画面（screens を設定していない・スクショだけ）は 8-3a のまま項目の行の高さ。画面の領域を全部の画面の箱に取ると、HTML の無い基準の graph と `/today` の例の配置も動き、`/today` の交差が 50 → 56 で 8-3a の上限（50）を超える。HTML の無い画面に空の大きな箱を出す意味も薄い。layout:（Next の layout）は抽出器が HTML を写さないので領域を持たない
2. **画面の領域の位置**: 名前の帯（26px）の下に、枠の内側（左右 1px）の幅で、ビューポートの比率の高さ。箱の高さは「帯 ＋ 画面 ＋ 1px」と「項目の行」の大きい方。項目のピンは箱の縁で、項目の文字は画面の上に重なる（読めるよう文字に暗い縁取り。`paint-order: stroke`）
3. **ビューポートの範囲**: `screen.width × height` を、縦 / 横 0.25〜2.5、幅と高さ 200〜4096 に比を保って収める（graph の値が極端でも箱と iframe が巨大にならない）。graph の `regions` は screen の座標なので、収めたビューポートの座標に直して使う
4. **空の `screen.regions` は無いのと同じ**（計測を使う）。screenshots 抽出器は `data-component` が 1 つも無いと `regions: []` を書くため、空の配列を優先すると HTML の計測が消える
5. **src は graph.json からの相対パスだけ**: スキームの付いた URL・`/` や `//` で始まる・`\` や制御文字を含むものは読まない。解いた URL がビューアと別の origin か、graph.json のディレクトリの外（`..`・`%2e%2e`）でも読まない（プレースホルダ）。ファイルで開いた graph は相対パスを解けないのでプレースホルダ
6. **読み込みの順**: 画面上の幅が 200px 以上で、表示の枠に掛かる箱のうち、見えている面積の大きい順（同じなら枠の中心に近い順）に 6 枚。決め直しは canvas の変換のたびではなく次のフレームで 1 回
7. **読めないとき**: `load` のあとに `contentDocument` が読めなければ（応答ヘッダの sandbox に allow-same-origin が無いなど）iframe を外し、その画面は以後読まない（`blocked`）。プレースホルダの文言は状態ごと（拡大すると表示・読み込み中・別の origin・URL で開くと表示・graph.json の外）
8. **画面の箱の SVG**: 画面の領域だけ塗らない（`fill-rule: evenodd` の穴の空いた塗り `screen-bg`）。枠の rect は透明の塗りでクリックを受ける（iframe の層は `pointer-events: none`）。レーンの背景は clip-path で画面の領域を抜く。iframe の外枠は白（背景を持たないページはブラウザと同じ白に見える）
9. **領域の枠**: 選択の経路（`lit.boxes`）に入る部品だけ、画面の領域の中に切り詰めて描く。画面の箱そのものの領域は描かない。画面が沈んでいても、部品が光っていれば枠は描く。hover では描かない（今の規則のまま）

### 9.6 レビューの指摘で決めたこと（2026-11-09。コードレビュー（high）とセキュリティレビュー）

指摘ごとに、直す前に失敗するテストを足した（2 乗のものは敵対的な入力を大きくして CPU 時間の上限で見る。`extractors/screens/src/__tests__/review-83b.test.ts` ほか）。

1. **screens/ の持ち主**: 消してよい・書いてよいのは、印（`screens/.stack-atlas-screens`）のあるもの（前回の build が書いた）か、無いもの（この build が作る）だけ（core の `screensDirState`）。印の無いディレクトリは、build も抽出器も書かずに警告する（`issues.json` の warning。消しも上書きもしない）。以前は抽出器が印の無い `screens/` に書いて印を足し、次の build が利用者のディレクトリを消していた
2. **入れ替え**: build は抽出器に出力先の中の一時ディレクトリ（`mkdtemp` の `.screens-staging-*`）を渡し、graph.json を書くときに前回の `screens/` を消して `rename` で入れ替える（`swapScreens`）。失敗した build（例外・設定の誤り）は前回の `screens/` と graph.json をそのまま残す。以前は抽出の前に消したので、失敗した build の後の graph.json が消えた画面を指した。一時ディレクトリはいつも消す。印の無い `screens/` の中は `unsafeOutputs` でも調べない（調べるのは消すか書くときだけ）
3. **スクショの書き出し先**: `screenshots.outDir` は build の出力先そのものだけ（下のディレクトリも警告して出力先にする）。スクショ抽出器は graph.json からの参照を `shots/<slug>.png` と書くので、下のディレクトリでは画像が開けなかった（参照のパスを直すより、受け付ける値を絞る方が簡単で正しい）
4. **不正なルートの URL**: サイトの中のパスにできない URL（`/../a`・壊れた `%`・段の中の `/`）は HTML を探さずに警告する。`index.html` になるのは根（`/`）だけ（`toSitePath` は根を空文字列、不正を undefined で返す）
5. **`<pre>` の直後の改行**: 字句の木で、`pre`・`listing`・`textarea` の開始タグの直後の改行を 1 つ捨てる（HTML の仕様）。書き出しで足す改行（ブラウザが捨てる分）と合わせて、ブラウザで描いた中身が元と同じになる（Chromium で確かめる）
6. **画面の大きさ**: 抽出器どうしのマージで、`screen.html` を出した側の幅・高さを使う（`mergeNodes`）。もう片方（スクショ）の regions は別の大きさで測った座標なので、大きさが違えば捨てる（ビューアが HTML を測る。3D の地図はスクショに枠を出さない）。以前は先に出た screenshots の viewport が残り、`screens.viewport` が効かなかった
7. **serve の CSP**: `/screens/` の下の判定は、最初の段を大文字小文字を区別せずに比べ、さらに実体（dev と inode）でも比べる。大文字小文字を区別しない FS では `/SCREENS/…`・`/%53creens/…`、別名のディレクトリ（screens/ へのリンク）でも同じファイルを返すため
8. **計測の待ち**: `loading="lazy"` の画像は待たない（縮小した iframe や表示の枠の外では読み込まれず、毎回上限の 3 秒まで待った）。消毒は `loading` を残す
9. **一本にしたもの**: 画面の名前は screenshots の `uniqueSlug`（英数字で始まらない・100 文字を超える名前は `r-<ハッシュ>`。スクショの名前も同じになる）。パスの中か外かは core の `pathWithin`（build と抽出器の読み書き）
10. **2 乗の解析**: コメントの終わり（`-->`・`--!>`）は位置を覚えて前から 1 回だけ探す。URL の前後の空白・srcset の末尾のカンマ・basePath の末尾の `/` は端から数える（正規表現の `[…]+$` をやめた）。next.config のコメントは前から 1 回だけ走査し、1 MB を超える next.config は値を読まずに警告する

    | 敵対的な入力 | 直す前 | 直した後 |
    |---|---|---|
    | `<!----!>` × 40000（320 KB、`-->` 無し） | 48.7 秒 | 14 ms |
    | `href` の途中の空白 40k | 4.2 秒 | 1 ms 未満 |
    | CSS の `url("…")` の途中の空白 40k | 4.5 秒 | 2 ms |
    | srcset のカンマ 40k | 5.0 秒 | 2 ms |
    | `normalizePrefix` の `/` 40k ＋ `a` | 4.3 秒 | 1 ms 未満 |
    | next.config の閉じていない `/*` × 40000（80 KB） | 2.8 秒 | 1 ms |

11. **SVG の data: URL の膨張**: 1 つの文書（画面の HTML・写す CSS ファイル）に埋め込む data: URL は合計 2 MB まで（`InlineBudget`。`AssetStore.verdict` の引数で省けない）。超えた参照は入れずに数え、info で報告する。消毒した HTML・CSS が 10 MB を超えたら書かない（警告）。以前は 256 KB の SVG を参照ごとに埋め込み、100 回で 34 MB、2000 回で文字列の長さの上限（RangeError）を超えて抽出器が落ちた。直した後は 100 回・2000 回とも 1.96 MB（埋め込み 6 回）
12. **制御文字**: screens が `issues.json` と要約に出す文字列（タグ名・rel・data-component の値・ルートのパターン）の C0・DEL・C1・双方向の上書きは `\u{1b}` の形にする（端末を操作させない）
13. **e2e の fixture-repo**（`fixture-repo: 画面の箱に iframe が出て…`）: d3b49e7（8-2b・8-3a を取り込んだ後）の配置では、開いた直後の表示（1440×900、倍率 0.6）で `/` の画面の箱が下端に掛かるだけで、画面の領域が表示の枠の外にある。読み込みの規則（枠に掛かる箱だけ読む）どおり読まれず、`measured['route:/']` が 0 のまま。配置は wiring（DOM に依らない）で決まり、ビューポートは CI と同じなので、手元だけの事情ではない。テストは箱を表示の上の方まで動かして（wheel）から測る

### 11.1 結論

- 今の配線図は、選択・解除・分岐・view のたびに SVG 全体を文字列から作り直している（`app.ts` の `render()` が `svg.innerHTML = …`）。箱の位置は選択で変わらない（配置は場面ごとに 1 回）ので、作り直す必要があるのは「どれが光り、どれが沈むか」だけ
- **SVG は場面（描く索引・配置・差分とメモの印）ごとに 1 回だけ作る。選択・分岐・view は、class の付け替えと「光る線の層」（選択の大きさに比例）の作り直しだけにする**（D114〜D116）
- class は**光る側にだけ**付ける（`lit`・`on`・`under`）。沈める側は根の `has-sel` と CSS の `:not()` で決める（D122）。付け替える要素の数が光る数に比例し、幽霊（差分）は要素に触らずに沈む
- 作り直しをやめても、沈める表現（要素の `opacity`）のままでは描画（ラスタ）が残って遅い。**沈める表現を塗りの不透明度（`fill-opacity` / `stroke-opacity`）に替え、`opacity` の transition をやめる**（D117。値は §11.5 の表）
- 選んだあとの再生がコマ落ちする主因は、球が着いた項目の点滅（フラッシュ）。filter の keyframe と、点滅のたびの強制レイアウトをやめる（D118）
- 効果（第 1 段の試作の実測。DPR 1。click → 画面に出るまで、中央値）: fixture-poly 40〜72ms → **24〜32ms**。合成 300 箱 192〜496ms → **56〜144ms**。実リポジトリの大きさ（310 箱）160〜384ms → **104〜128ms**。再生は 1.5 秒に 6 コマ → 81 コマ（合成 300 箱・密・全体表示）。実装したあとの数字（DPR 1・2、実際のクリック）は §11.14
- 半分の幅（2 面）の部品は、窓の幅（`@media`・`100vw`）で大きさを決めているのが原因。**面の幅で決める**（D121。§11.9）

### 11.3 構造: 場面を 1 回作る / 選択で付け替える

**場面（D114）**: 1 回の「全体を作る」の入力を 1 つの値にする。中身は、描く索引（差分があれば幽霊を足した graph の索引）・配置・差分の印・メモの印（角を折る箱）。場面から作った DOM の側は、要素の Map（箱 id・項目の ref・線のキー・host id → 要素）と前の塗りの計画を持つ（`sceneView.ts`）。

| 変わるもの | すること |
|---|---|
| graph を開く・ドロップ、差分（`?prev=`）、メモの印（角を折る箱が増減） | **場面を当てる（`setScene`）= 全体を作る**。`renders` はこの回数。要素の Map と前の計画は必ず作り直す。作ったあと、今の選択を当て直す |
| 選択・解除（箱・項目・線・型・host・地図の group） | **付け替え（`paint`）**。`paints` を足す |
| 分岐（variant の表）・view を選ぶ | 付け替え 1 回（分岐と選択を当ててから） |
| 部品の領域（`g.regions`） | 層の中身だけ作り直す（今も計測のあとにしている。選択に入る部品だけなので小さい） |
| 球 | `g.balls` の中だけ（今のまま） |
| 移動・拡大 | `g.view` の transform だけ（今のまま） |
| hover（選択が無いときだけ） | class の付け替え（要素は Map で引く。`querySelectorAll` を使わない） |

**折りたたみ（Q19、8-8）への継ぎ目**: 配置を mount のときの定数として握っていた 5 か所（`planDraw` の結果・画面の層・canvas の大きさ・`Player`・分岐の表）は、今の場面から読む。`setScene` は (1) 違う配置・索引で何度でも呼べる、(2) 当てたあと選択を当て直す、(3) `Player` は周回の中の同じ割合の位置から続ける（速さを変えたときと同じ `rescaleTime`）、(4) 視点は動かさない（どこを映すかは呼ぶ側が決める。自動で全体表示にしない）。8-7 では場面は 1 つ（開いたとき）と、メモの印が変わったときの作り直しだけだが、同じ場面を 2 回当てて DOM が同じ・選択が残ることをテストで固定する（§11.10）。選ぶ側の索引（今の graph の索引）は 8-7 では 1 つのまま。

**塗りの計画（D115）**: 「どの要素にどの class を付けるか」を純関数 `paintPlan(場面, 分岐, 光るもの)` に切り出す（DOM に触らない。`packages/viewer/src/wiring/paint.ts`）。返すのは、箱・host・項目・線ごとの「選択と分岐で変わる class」（付くものだけ。光る箱 `lit[ start]`、光る host `lit`、光る項目 `on[ start]`、今の分岐に無い項目 `off inactive`、光る線の下に隠れる基の線 `under`、今の分岐に無い線 `inactive`）、切れた線ごとの「光るか」、光る線の層の markup、選択の有無（根の `has-sel`）。**全体を作る経路も付け替える経路も同じ計画を使う**（全体を作るときは計画の class を markup に書き、付け替えるときは前の計画との差だけ `class` 属性に当てる）。2 つの経路の結果が同じであることをテストで固定する（§11.10）。

計画の外に状態を残さない（レビューの指摘 2。`innerHTML` が毎回消していたものを、付け替えでも消す）:

- **hover**: 付け替えの最初に `hov` を全部外す（選択中は hover が効かない。D31）。解除したときポインタが箱の上のままなら、その箱の hover を出し直す（今は作り直した要素に `mouseover` が来て出る。要素が同じだと来ないので、最後に入った箱を覚えておく）
- **幽霊（差分）**: 要素ごとの class は変えない。根の `has-sel` で沈む（箱・host・線・項目とも）
- **点滅**: `player.setup` が、走っているアニメーションと「ずらし」のタイマーを全部取り消す（解除・選び直しのあとに前の選択の点滅が続かない）
- **分岐の表**: 付け替えの最後に `table.refresh()`（対のチェックと、view で既定に戻した分岐を映す）
- **切れた線**: 送り側の箱が光る切れた線は、写しを作らずに**要素ごと**光る線の層へ移し、外れたら基の層へ戻す（数が少ない。`data-broken`・`<title>` は 1 つのまま、選択中も吹き出しが出る）

要素は、全体を作ったときに 1 回だけ `Map` に入れる。付け替えと点滅は `querySelector` を使わない。

**層の順（D116）**:

```
今:   lanes → base-wires → hosts → base-boxes → lit-wires → lit-boxes → regions → balls
これ: lanes → base-wires → hosts → lit-wires → boxes → regions → balls
```

- 箱は 1 つの層に置いたまま動かさない（class だけ）。光る箱を層の間で動かす試作は遅かった（合成 300・密で 253 箱を動かすと 184 / 128ms、動かさないと 144 / 88ms）
- 線は全部 `base-wires` に置いたまま。光る線は `under` の class で隠し（`visibility: hidden`。`display: none` はレイアウトが走る）、`lit-wires` に光る区間（`data-seg`）・cache の中の区間・当たり判定（`data-wire`）を作る。この層だけ選択のたびに作り直す（要素の数は光る線に比例）
- 分岐の表の橋は `lit-wires` の直前（= `hosts` の直後。今と同じく光る線と箱の下）。層を名前で探して見つからないと橋が最前面に付いてピンのクリックを奪うので、層の要素を直接渡し、位置を e2e で固定する

### 11.4 守る規則（D31 = docs/15 §3.6）

|---|---|

**見た目・操作で変わる所（3 つ。Q21 で了承）**:

1. 選ぶ・解くときの 0.18 秒のフェードが無くなる（すぐ切り替わる）。transition があると数フレームにわたって全体を描き直す。画面の箱の iframe（`.wv-screen`）の transition も外す（SVG だけ先に切り替わって iframe が遅れて沈むのを防ぐ）
2. 光る線の当たり判定（幅 12px）が箱の下になる。今は光る線の層が沈んだ箱の上にあり、線より先に当たるのは光る箱の項目・ピンだけ。これからは箱が全部線の上なので、沈んだ箱の縁から 6px 以内を通る光る線は、その 6px だけ箱（とその項目・ピン）のクリックが勝つ。縦のトラックは通り道の端から 12px 以上内側を通るので通常は起きない。「箱から 6px 以内を通る線が 0」を、差分（幽霊を足した配置）も含めてテストで固定する（§11.10）
3. 光る箱のぼかし（`drop-shadow`）は**始点の箱だけ**に残し、ほかの光る箱は縁の太さと色だけにする。球のぼかしは半透明の円を重ねて代える。点滅は白くするだけ（ぼかし無し）

Esc のあとの hover: 解除したときポインタが箱の上にあれば、その箱の hover はすぐ出る（§11.3）。

### 11.5 沈める表現（D117・D122）

- 今: `.box.dim { opacity: .15 }`・`.item.off { opacity: .35 }`・`.wire.thin { opacity: .35 }` など、要素ごとの `opacity`。入れ子では掛け算になる（沈んだ箱の中の光らない項目は 0.15 × 0.35）
- これ: 要素の `opacity` は使わず、塗りの不透明度（`fill-opacity` / `stroke-opacity`）にする。**塗りの不透明度は子へ継承されるだけで掛け算にならない**（レビューの指摘 1）ので、箱の係数（`--bo`）と項目の係数（`--io`）を CSS の変数で持ち、項目には `calc(var(--bo) * var(--io))` を当てる。値は下の表（= 今の積）。係数は `dim.ts` の定数が正で、`style.css` の「沈める表現」の区画（1 か所。ここを戻せば元の濃さに戻せる）と合っていることを単体テストで確かめる

読み方:

- **fixture-poly は 50ms に届く**（試作 24〜32ms）
- **合成 300 箱は届かない**: 疎で 56〜64ms、密で 72（開いた直後）〜144ms（全体）。付け替えは選択の大きさに関係なく全要素のスタイルと描画が変わる
- 実リポジトリの大きさは 100〜130ms（今の 1/2〜1/3）

**幕の案（D119。採らない）**: 沈める側に触らず、基の層の上に背景色の幕（85%）を 1 枚置き、光る箱だけ幕の上へ動かす。変わる要素が光る側だけなので、小さい選択では速い（実リポジトリ 40ms）。ただし (1) 選択が大きいと付け替えより遅い（151 箱で 152ms）、(2) 沈んだ箱のラベルが 15% で残る（D31 の「ラベルを消す」に別の手当てが要る）、(3) 沈んだ線が 12% でなく 5% になり、レーンの色と host の枠も沈む、(4) 経路が 2 つになる。

**Q21（決まり。2026-11-10）**: 案 A。付け替え（D114〜D118・D122）だけで進める。幕（案 B）と canvas / WebGL（案 C）は記録として残す。§11.4 の「変わる所」3 つ（フェード無し、光る箱のぼかしは始点だけ、点滅のぼかし無し）は進めてよい。沈める規則は CSS の 1 か所にまとめ、戻せるようにする。

**時間の目標は、実装のあとに測ってから置く**（レビューの指摘 3）。第 1 段で書いた「疎 80ms・密 100ms / 160ms・ハンドラの JS 20ms」は、表の数字（疎・全体の解除 96ms）と合わず、ぶれ（±20%、8ms 刻み）の中に置いていたので取り下げる。測った数字と、届いた所・届かない所は §11.14。

受け入れ条件（構造。CI で確かめる）:

- 選択・解除・分岐・view で `renders` が増えず、`paints` が増える。箱・項目・線の要素が選択の前後で同じ（要素の同一性）
- 付け替えた DOM が、その状態で全体を作った DOM と同じ（`g.view` の outerHTML。球の層の中を除く）。入力は、選択 10 通り以上 × 分岐、実マウスの hover → クリック、再生中に解除、分岐の表を出したまま、差分、メモの印
- 同じ場面を 2 回当てても DOM が同じで、選択が残る
- 時間は CI では確かめない（ぶれる。D120）。計測のスクリプトで測って docs に書く

### 11.9 半分の幅の部品（fixture-poly の 2 面で確かめた）

### 11.12 やらないこと・確かめたこと・推定

- やらない: 配置を変える、画面の外の要素を間引く（仮想化）、canvas / WebGL へ替える（Q21 の案 C）、group の折りたたみ（Q19。8-8）、3D の地図の描画の直し（2 面の実測で律速ではない）
- 確かめた（実測）: §11.2 の今の数字、§11.8 の試作の数字、§11.5 の A と R、箱を動かすと遅いこと、transition があると遅いこと、点滅と強制レイアウトが再生を止めていること、§11.9 の重なりと切れ（スクショ）
- 推定: 塗りの不透明度が速い理由
