# 18. 設計: 配線図のビューア（Phase 8-3）

作成: 2026-11-09。`docs/15` §3.5〜§3.9（たどる・表示・折りたたみ・名前付きの始点）と `docs/14` §3.3（ビルド成果物の画面）を、8-0 の配線図（`packages/viewer/src/wiring/`・`packages/wiring/src/layout.ts`）の上に実装する設計。8-2 で graph が項目の単位になり、箱が 50（fixture-poly）〜数百（実リポジトリ）に増えた。今のレイアウトでは fixture-poly の 8-2a の出力が 3348×6486 の縦長になり、全体表示で文字が読めない。設計レビュー（§7）を反映した版。

## 1. 結論

- **レイアウトを作り直す（ELK は入れない）**。レーンは今のまま左から右。箱の多いレーンだけを、呼び出しの深さの境目で列に割り、図全体を 16:10 に近づける。列を 2 つ以上またぐ線には高さ 0 の通過点を置いて、列の中の順と縦の位置を決める計算に参加させる（Sugiyama 法のダミー）。host の枠（Lambda など）は中を先に配置して 1 つの塊として扱う。**配置は graph ごとに 1 回だけ決め、選択や分岐の切り替えでは箱を動かさない**
- **group の自動の折りたたみはしない**（docs/15 §3.8 の全体表示の折りたたみは保留。Q19）。ユーザーの要望「I/O は常に全部開いておく」「畳んだ箱と束の線は分かりにくい」を優先する。代わりに、開いた直後は**読める倍率**（項目の文字が 6px 以上）で画面の箱のあたりを映し、全体は縮小して見る。実リポジトリ（8-5）の画面を見てもらってから、畳むかどうかを決めてもらう
- **画面の箱の中にビルド成果物の HTML を出す**（docs/14 §3.3）。新しい抽出器 `screens` が HTML を写して許可リストで消毒し、ビューアは `allow-scripts` 無しの sandbox の iframe を SVG の下の層に縮小して置く。`serve` は画面の HTML に CSP の応答ヘッダ（`sandbox` 付き）を付ける。依存は足さない
- **views・memos・diff を v2 に**。diff は `@stack-atlas/wiring` に移す（ビューアは core に依存しない。D44）。検証の警告は題名の横の文字のリンクにする

## 2. 全体像

```
graph.json（v2）
   │
   ▼
@stack-atlas/wiring
   ├─ layout（§3.1）: レーン → host の塊 → レーンを列に割る → 通過点 → 列の中の順 → 縦の位置 → 直交配線
   │                   （graph ごとに 1 回。選択・分岐の状態は入力に取らない）
   └─ diff（§3.4）: core から移す（core は再 export）
   │
   ▼
viewer/wiring
   ├─ 画面の層（§3.3。iframe。SVG の下）＋ SVG（箱・線・球・画面の領域の枠）
   ├─ 操作: クリック・hover・Esc（今のまま）、views の選択
   └─ メモ・差分・警告のリンク
```

## 3. 構造

### 3.1 レイアウト（`packages/wiring/src/layout.ts`）

8-0 の規則（重心で並べる、線の数で隙間を決める、直交配線、線は箱を通らない、項目は相手の並びに合わせて並べ替える）は残し、次の手順に置き換える。8-0 の縦長の原因は、重心で置く位置が下へ連鎖することと、1 レーン = 1 列で箱が縦に積まれること（docs/16 §10 の記録）の両方。

1. **レーン**: `runtime` → レーン（今のまま。箱の無いレーンは出さない）
2. **host の塊**: 同じ `host` の箱の集まり（Lambda・ECS・Aurora の枠）は、まず中だけで手順 3〜7 を行って大きさを決め、外側の配置では 1 つの箱（塊）として扱う。外の線は塊の縁を通って中の項目のピンに着く（枠は背景で、箱ではないので線が横切ってよい）。塊の中の箱は中の配置のまま動かない。外の箱が塊に重なることは無い
3. **層（呼び出しの深さ）**: 同じレーン（塊の中なら塊の中）の箱どうしの線のうち、**呼び出し・props・render・http の向きの線**（`reply` と、呼び出しでない参照の `_` の線を除く）で有向グラフを作る。閉路は DFS の後退辺を外して切る。最長経路で層を付ける。**入ってくる線の無い箱は、後続の層の最小値のすぐ左**に置く（列 0 に集めない。`fn:getEntries` が画面と同じ層に並ばない）
4. **レーンを列に割る**: 最初は 1 レーン = 1 列。全体の幅と高さから縦横比を出し、16:10 より縦長なら、**いちばん高いレーンを層の境目で 1 つ割る**（層の高さの累積がほぼ半分になる所）。16:10 に近づかなくなるか、割れる境目が無くなるまで繰り返す。割った列には層の順に箱を入れる。レーンの背景はそのレーンの列を全部含む
5. **通過点**: 2 つ以上の列をまたぐ線（レーンをまたぐ線も含む）には、間の列ごとに高さ 0 の通過点を置く。通過点は列の中の順と縦の位置の計算に参加し、線はその y を通る。`reply` の線は、対になる呼び出しの線の通過点の隣を逆向きに通る（呼び出しと戻りが並んで走る）
6. **列の中の順**: 初めの順は宣言の順（items の `row`、なければ graph の nodes の順。docs/15 §8 #13・#16）。仮の y は初めの順に積んだ位置。左右交互に 8 往復、**項目のピンの y の重心**で並べ直す。同じ `group`（無ければ file のディレクトリ）の箱は列の中で隣り合わせる。同点は初めの順で崩す（決定的）
7. **縦の位置**: 左から右へ、箱（と通過点）ごとに「左側でつながっている項目のピンの y の中央値」を目標にし、順序を保ったまま重なりを最小の移動で解く（PAVA）。左側に相手が無い箱は今の y を目標にする。右から左へも同じことをして、2 つの解の平均を取る（制約が線形なので平均も重ならない）。隙間の大きさ（そこを通る線の数 × 8px ＋ 余白）で y が変わるので、手順 6〜7 を 3 回繰り返す
8. **列の幅**: 列の中でいちばん幅の広い箱（画面の箱は通常の 2 倍）。通り道の幅はそこを通る縦の区間の数 × 8px ＋ 余白で、区間はトラックに左詰めで割り当てる（重ならない）
9. **配線**: 直交の折れ線。通過点の y を順に通る。後ろの列へ戻る線（同じ列の上下や、通過点の無い短い戻り）は今の「隙間を通る回り道」

**配置は graph ごとに 1 回だけ**決める。選択・分岐の切り替え・下流だけの絞り込みでは箱を動かさない（docs/15 §3.6「選択は沈めるだけで形は変えない」、docs/05）。build 時に配置を graph.json に埋める（docs/16 §10、D44 の後半）のは今回もしない。

性能の目安: 箱 300・項目 3000・線 1000 で、配置 1 回が CPU 時間で 300ms 以内。クリックから光るまで 50ms 以内（配置をし直さないので、たどる計算だけ）。

うまくいかないとき（受け入れ条件 §4 を満たせないとき）は、**build 時に ELK で配置を計算して graph.json に埋める**案をユーザーに出す（依存の追加は確認が要る）。

- docs/15 の古い記述（§3.5 の最後の行「全体表示は箱と束の線だけで、項目は出さない」、§3.8 の 3 つ目「関係する項目だけ開く」）は、この節と docs/15 §3.6 で置き換える

### 3.3 画面（ビルド成果物の HTML）

#### 契約

- v1・v2 の `screen` に `html`（graph.json からの相対パス）と `source`（`next-export` / `dir`）を足す（docs/14 §3.3 の契約）。v1 の `graph.schema.json`・`types.ts`・`docs/03` も直す（v1 の `screen` は `additionalProperties: false`）。`upgradeGraph` は `screen` をそのまま写す
- graph.json に `screen.regions` があればビューアの計測より優先する（今の規則。空の配列は無いのと同じ。§9.2 の 4）

#### 集める側: 抽出器 `screens`（`extractors/screens`）

- 設定 `screens: { repo, from: next-export | dir, dir, routes, viewport }`。`next-export` は nextjs-app が読む `next.config` の `output`・`distDir`（既定 `out`）に加え、**`trailingSlash`・`basePath`・`assetPrefix`** を読む（`basePath` があると `/_next` の写しが外れるため）。`dir` は任意のディレクトリ
- `route:` ごとに HTML を決める（`/` → `index.html`、`/a` → `a.html` か `a/index.html`（trailingSlash）、動的ルートは `routes` のサンプル）。無ければ何もしない（今のプレースホルダ）
- **消毒**（許可リスト。自前の字句解析。D63）:
  - 字句から**書き直す**（元の文字列を写さない）。doctype は先頭に残し、CSP の meta を **`<head>` の最初の子**に入れる（`<head>` を決められない文書は出さない）: `default-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; base-uri 'none'; form-action 'none'`
  - タグごとの属性の許可リスト。URL を持つ属性（`src` `href` `srcset` `poster` `background` `xlink:href` `ping` `formaction` `action` `data` `cite`）は全部、文字参照を解き空白・制御文字を除いてから scheme を見る。残すのは相対パスと、画像・フォントの `data:` だけ
  - まるごと落とす: `script` `noscript` `iframe` `object` `embed` `base` `meta[http-equiv]` `svg` `math` `template` `title` `textarea` `xmp` `noembed` `noframes` `plaintext`、コメント・CDATA、`on*` 属性、`<link>` の `rel=stylesheet` 以外。解析できない所（閉じていないタグ・未知の構文）は要素ごと落とす
  - `form` は `div` に書き換える（2026-11-09 変更（8-3b）。中身ごと落とすと部品のルート要素の `data-component` が消え、領域が取れない。属性は div の許可リストで、送信に関わる属性は落ちる。CSP の `form-action 'none'` と `allow-forms` 無しはそのまま）
  - CSS（`<style>` の中身・`style` 属性・写す CSS ファイル）は CSS の字句解析を通す。`@import`・`image-set()`・外部の `url()` を落とし、エスケープ（`u\72l(`）は解いてから判定する
- **資産の写し**: 同じ出所の CSS・フォント・画像（`/_next/static/...`、`public/`）だけ。読む元は realpath にして export のディレクトリと public の中に限り、シンボリックリンクは辿らない。拡張子は許可リスト（css woff woff2 ttf otf png jpg jpeg gif webp avif svg ico）。写した名前は内容のハッシュ（`_assets/<hash>.<ext>`）。**svg はファイルにせず**、画像として読む所（img の src・srcset、CSS の url() など）に `data:image/svg+xml;base64` で埋め込む（上限 256 KB。2026-11-09 変更（8-3b）。ファイルの SVG は応答ヘッダの無い配信で直接開くと script がビューアの origin で動きうる）。外部 URL と落とした要素の数を `issues.json` に出す
- **regions のカバー率**（docs/14 §3.3 の 4）: route ごとに「HTML の `data-component` で解けた部品の数 ÷ その画面から呼び出しでたどれる部品の数」を `issues.json` に出す。0 なら警告（`data-component` を付けるきっかけ。ビルドは止めない）
- 出力: `out/screens/<slug>/index.html`、箱の `screen = { html, width, height, source }`。書く先は出力先の中だけで、シンボリックリンクを確かめる（build の既存の検査）
- `screenshots` 抽出器はそのまま。両方あれば `screen.html` を優先して描く
- **後回し**（8-4 のハーネスで）: fixtures モードのビルド（対象アプリの変更が要り、エージェントが提案する）、`.stack-atlas/screens/*.html`（wireframe）と `regions.yaml`、外部 URL を `validate --strict` でエラーにすること（`--strict` は 8-4）

#### serve

- `/screens/**` の応答に `Content-Security-Policy: sandbox allow-same-origin; default-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; base-uri 'none'; form-action 'none'` を付ける。HTML をタブで直接開いても sandbox が効く。S3 / CloudFront で配るときに同じ応答ヘッダを付ける方法を docs/11 に書く

#### 描く側: ビューア

- 画面の箱（kind `screen`）に `screen.html` があれば、箱の中に縮小した実 DOM を出す。**iframe の層は SVG の下**に置き（SVG の背景は透明にし、画面の箱の中だけ抜く）、層全体を `pointer-events: none`。canvas と同じ移動・拡大の変換を掛ける。iframe は `sandbox="allow-same-origin"`（`allow-scripts`・`allow-forms`・`allow-popups` は付けない）、`referrerpolicy="no-referrer"`
- 画面の箱の大きさ: 幅は通常の 2 倍、高さは「viewport の比率の高さ」と「項目の行の高さ」の大きい方。HTML はビューポートの高さで切る（縦に長いページは上だけ）。項目のピンは箱の縁（2026-11-09 決定（8-3b）: 画面の領域を取るのは `screen.html` のある箱だけで、名前の帯の下に置く。§9.2）
- 読み込み: 画面上の幅が 200px 以上の箱だけ読む（`loading="lazy"` は変換の下で距離が決まらないので使わない）。同時に生かす iframe は 6 枚まで、画面から外れたら外す
- **部品の領域**: `load` 後、`fonts.ready` と画像を待って（上限 3 秒）`[data-component]` を測り、`comp:<名前>` → `hook:<名前>` → 末尾一致の順で箱 id に解く（screenshots 抽出器と同じ規則）。選んだ経路に入る部品の領域だけ、**SVG の側に**枠を描く（ラベルは出さない）
- 沈んだ画面は iframe の不透明度も他の箱と同じに下げる
- `contentDocument` が読めないとき（別 origin・ファイルを落として開いたとき）は、プレースホルダと graph の regions で描く

### 3.4 views・memos・diff・警告

- **views**: 題名の横に views の名前のメニュー（`select`）。選ぶと分岐の状態を既定に戻してから `variants` を当て、`start`（箱・項目・線のどれでも）から選択を始める。ほかをクリックしたらメニューは空の選択に戻る。`?view=<id>` で開ける（共有用）。views が無ければ出さない
- **memos**: `memos.json`（キーは箱 id。v1 と同じ）を読む。メモのある箱は**右下の角を折った形**で描く（右上は分岐の表、左上の外は種類の位置）。箱を選んだとき、左下に固定の札（不透明の背景、光る層の上）で本文を出し、その場で編集できる（3D の地図と同じ保存の仕組み: localStorage と、`serve --repo` なら `POST /api/memos`）。型をクリックしたときは型の id のメモ、箱のメモに加えて group（v1 の箱の id。D56）のメモがあれば同じ札に並べる。孤立したメモの判定は箱・型・group の id を見る
- **diff**: `?prev=<前の graph.json>`。前が v2 なら、`diffGraphsV2` で比べ、**今の graph に前にしか無い箱と線を足した graph** を配置して、足した分を灰の点線（幽霊）で描く。今だけにある箱・項目・線は緑の縁、`type` / `wireType` が変わった項目も緑の縁。消えた項目は箱の中に灰の点線の行で残す。前が v1 なら差分は出さず、題名の横に「前の graph が v1 です」（ビューアは v1 → v2 を変換できない）。`diffGraphsV2` は `@stack-atlas/wiring` に移し、core は wiring から再 export する
- **警告**: 検証の警告は図の上の枠をやめ、題名の横に文字のリンク（`警告 2 件`。3D の地図へのリンクと同じ並び）で出し、クリックで一覧を開く

1. **初めの順も塊を割らない**: 初めの順を y の順だけで並べていたので、線の無い列（往復が良くならず初めの順が残る）で host の中の箱の間に外の箱が入り、枠が外の箱に重なった。初めの順も並べ直しと同じ `sortWithGroups`（host・group の塊を隣り合わせる）にした。塊を守ると `/today` の交差が 45 → 56 になったので、**最後の回に入れ替え（`Placer.refine`）**を足した: 隣り合う単位（host・group）・単位の中の group・group の中の箱・自由な束と隣の塊を入れ替え、並べ方の悪さが減るものを残す。交差の増減は入れ替えた塊の線の組だけで数え、同じ列の中の線の長さは変えた所だけ積み直して数える。塊の数 ×（塊の数 ＋ 同じ列の中の線）が 100 万を超える列は省く。毎回でなく最後の回だけなのは速さのため（毎回だと基準の graph 411・合成の冷えた 1 回目 250〜300ms）
2. **切れている線の印**: 印（受ける側の箱の 16px 手前の縦の短い線）が、いちばん右のトラック（列の 16px 手前）と同じ x になり、線が縦で終わって印が線の上に描かれた（`/today` の b0）。切れている線の最後の通り道は、いちばん右のトラックと箱の間に 2 × BROKEN_CUT（32px）を空ける（トラックの位置は変えず、右に足す）。線は印の手前で 16px 以上の横の区間で終わり、印はどの縦の区間にも重ならない
3. **並べ方の悪さの物差し**: 2 回目からの回の基準は PAVA の位置で、往復の後は積んだ位置で測っていた（同じ列の中の線の長さが食い違う）。悪さは並びだけで決まる値にし、いつも列を上から積んだ位置（`sy`）で測る。基準の graph・`/today`・合成の graph では数は変わらない

### 9.2 §3.3 から決めた・変えた所

1. **画面の領域を取るのは `screen.html` のある画面の箱だけ**（kind `screen` で html が空でない文字列）。html の無い画面（screens を設定していない・スクショだけ）は 8-3a のまま項目の行の高さ。画面の領域を全部の画面の箱に取ると、HTML の無い基準の graph と `/today` の例の配置も動き、`/today` の交差が 50 → 56 で 8-3a の上限（50）を超える。HTML の無い画面に空の大きな箱を出す意味も薄い。layout:（Next の layout）は抽出器が HTML を写さないので領域を持たない
2. **画面の領域の位置**: 名前の帯（26px）の下に、枠の内側（左右 1px）の幅で、ビューポートの比率の高さ。箱の高さは「帯 ＋ 画面 ＋ 1px」と「項目の行」の大きい方。項目のピンは箱の縁で、項目の文字は画面の上に重なる（読めるよう文字に暗い縁取り。`paint-order: stroke`）
3. **ビューポートの範囲**: `screen.width × height` を、縦 / 横 0.25〜2.5、幅と高さ 200〜4096 に比を保って収める（graph の値が極端でも箱と iframe が巨大にならない）。graph の `regions` は screen の座標なので、収めたビューポートの座標に直して使う
4. **空の `screen.regions` は無いのと同じ**（計測を使う）。screenshots 抽出器は `data-component` が 1 つも無いと `regions: []` を書くため、空の配列を優先すると HTML の計測が消える
5. **src は graph.json からの相対パスだけ**: スキームの付いた URL・`/` や `//` で始まる・`\` や制御文字を含むものは読まない。解いた URL がビューアと別の origin か、graph.json のディレクトリの外（`..`・`%2e%2e`）でも読まない（プレースホルダ）。ファイルで開いた graph は相対パスを解けないのでプレースホルダ
6. **読み込みの順**: 画面上の幅が 200px 以上で、表示の枠に掛かる箱のうち、見えている面積の大きい順（同じなら枠の中心に近い順）に 6 枚。決め直しは canvas の変換のたびではなく次のフレームで 1 回
7. **読めないとき**: `load` のあとに `contentDocument` が読めなければ（応答ヘッダの sandbox に allow-same-origin が無いなど）iframe を外し、その画面は以後読まない（`blocked`）。プレースホルダの文言は状態ごと（拡大すると表示・読み込み中・別の origin・URL で開くと表示・graph.json の外）
8. **画面の箱の SVG**: 画面の領域だけ塗らない（`fill-rule: evenodd` の穴の空いた塗り `screen-bg`）。枠の rect は透明の塗りでクリックを受ける（iframe の層は `pointer-events: none`）。レーンの背景は clip-path で画面の領域を抜く。iframe の外枠は白（背景を持たないページはブラウザと同じ白に見える）
9. **領域の枠**: 選択の経路（`lit.boxes`）に入る部品だけ、画面の領域の中に切り詰めて描く。画面の箱そのものの領域は描かない。画面が沈んでいても、部品が光っていれば枠は描く。hover では描かない（今の規則のまま）
10. **名前の解き方の正本を wiring に**: ビューアは抽出器に依存しないので、`resolveRegionRef` を `@stack-atlas/wiring` に置き、core が再 export し、screenshots 抽出器はそれをそのまま出す（screens 抽出器のカバー率も同じ関数）。一致はテストで固定（同じ関数であること）
11. **計測の上限**: 1 画面で `[data-component]` を 2000 個まで

### 9.5 気づいたこと（直していない）

- 不透明度の確かめは当てた値（`style.opacity`）で見る。計算値は CSS の transition の途中の値で、手元の Chrome でヘッドレスを並列に走らせると transition が進まず 0.15 のまま止まることがあった（当てた値は 1）
- 光る画面の箱は枠の `drop-shadow` が内側にも広がり、画面の下端がうっすら青くなる
- fixture-poly の `next/font` の woff2 は 64 バイトの合成で、Chrome が「Failed to decode downloaded font」を console の warning に出す（e2e はエラーだけ見る）
